### Test the model against clear expectations

Before choosing a model, write down relationships that should hold for the intended use. The following code checks expected close pairs, expected distant pairs, and analogy answers. Each check reports a pass, a failure, or a skip when a word is unknown.



The checks require close pairs above 0.5 and far pairs below 0.3. Analogy checks compare the predicted capital with an expected word. Unknown words are reported as skipped, so a missing vocabulary entry is not mistaken for a passed test.

```python
# kind "close":   similarity must be above 0.5
# kind "far":     similarity must be below 0.3
# kind "analogy": france : paris = a : expected
CHECKS = [
    ("close",   "sofa",       "couch",     None),
    ("close",   "waiter",     "server",    None),
    ("far",     "sofa",       "banana",    None),
    ("far",     "cheap",      "expensive", None),
    ("far",     "good",       "bad",       None),
    ("analogy", "kazakhstan", None,        "astana"),
    ("analogy", "japan",      None,        "tokyo"),
]

def run_checks(kv, name):
    print(name)
    for kind, a, b, expected in CHECKS:
        if a not in kv or (b and b not in kv):
            print(f"  SKIP  {a} / {b}: unknown word")
            continue
        if kind == "analogy":
            got = analogy("france", "paris", a, kv)
            ok, detail = got == expected, f"capital of {a}: got {got}, expected {expected}"
        else:
            s = kv.similarity(a, b)
            ok = s > 0.5 if kind == "close" else s < 0.3
            detail = f"{a} / {b} should be {kind}: {s:.2f}"
        print(f"  {'PASS' if ok else 'FAIL'}  {detail}")

run_checks(glove, "GloVe")
run_checks(yelp_vectors, "Yelp Word2Vec")
```


**Saved output:**

```text

  FAIL  waiter / server should be close: 0.07
  PASS  sofa / banana should be far: 0.22
  FAIL  cheap / expensive should be far: 0.77
  FAIL  good / bad should be far: 0.77
  FAIL  capital of kazakhstan: got almaty, expected astana
  PASS  capital of japan: got tokyo, expected tokyo
Yelp Word2Vec

  PASS  waiter / server should be close: 0.94
  PASS  sofa / banana should be far: 0.27
  FAIL  cheap / expensive should be far: 0.68
  FAIL  good / bad should be far: 0.69
  SKIP  kazakhstan / None: unknown word
  FAIL  capital of japan: got carlo, expected tokyo
```



#### Interpret the checks

- **Both models place opposites close together.** The `cheap`/`expensive` and `good`/`bad` failures repeat the context-sharing limitation seen in the toy example.
- **GloVe scores `waiter`/`server` at 0.07.** In its news/Wikipedia data, `server` often refers to a computer. A single vector mixes those senses. Its Kazakhstan capital analogy also gives the wrong expected answer.
- **Yelp Word2Vec passes the synonym checks**, but its Japan-capital answer is `carlo`, associated with Monte Carlo. Restaurant reviews are poor training material for capital-city analogies.

A model's knowledge depends on the text it read. For the furniture shop, the next check is whether it even knows the words customers search for.



```python
furniture_queries = ["sofa", "couch", "armchair", "recliner", "bookshelf", "wardrobe",
                     "dresser", "nightstand", "ottoman", "mattress", "headboard", "loveseat"]

for name, kv in [("GloVe", glove), ("Yelp Word2Vec", yelp_vectors)]:
    missing = [w for w in furniture_queries if w not in kv]
    print(f"{name:14} knows {len(furniture_queries) - len(missing):2} of {len(furniture_queries)}   missing: {missing}")
```


**Saved output:**

```text
GloVe          knows 12 of 12   missing: []
Yelp Word2Vec  knows  8 of 12   missing: ['armchair', 'recliner', 'bookshelf', 'headboard']
```



GloVe contains all twelve test furniture words. The Yelp model is missing four: `armchair`, `recliner`, `bookshelf`, and `headboard`. Restaurant reviews rarely discuss furniture, and a vector model cannot expand a word outside its vocabulary.

For this catalogue, the example chooses GloVe, while remembering that related words and opposites can produce bad expansions.
