### Step 4: adjust the vectors after an answer

Let $p$ be the predicted probability and $y$ the correct label: 1 for a real pair, 0 for a fake pair. Update the center vector with:

$$v \leftarrow v - \eta \, (p - y) \, u$$

Read the update in order:

1. Calculate the error, $p-y$.
2. Multiply the error by the neighbor vector $u$.
3. Scale the change by the learning rate $\eta$, which sets the step size.
4. Subtract that change from the old center vector $v$.

This is the gradient-descent idea used earlier in the course: change parameters a little to reduce error.

- For a **real** pair with $p=0.3$, error $= 0.3 - 1 = -0.7$. Subtracting a negative change moves $v$ toward $u$, making the next dot product larger.
- For a **fake** pair with $p=0.8$, error $= 0.8 - 0 = +0.8$. The change moves $v$ away from $u$.

The following code puts all four steps together on the twelve sentences.

The update follows [[EN/Lectures/9 - Logistic Regression/9.4 - Gradient Descent with Two Features|gradient descent with two features]].



The toy code uses five-dimensional vectors, three fake neighbors per real pair, and learning rate 0.05. Fake-word probabilities are proportional to frequency raised to 0.75. `v_old` lets the neighbor-vector update use the center vector before that update.

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

print("sigmoid of -2, 0, 2:", sigmoid(np.array([-2, 0, 2])))

index = {w: i for i, w in enumerate(vocab)}
pairs = [(index[w], index[s[j]])                                       # step 1
         for s in toy for i, w in enumerate(s)
         for j in range(max(0, i - WINDOW), min(len(s), i + WINDOW + 1)) if j != i]
print("training pairs:", len(pairs), " first three:", [(vocab[c], vocab[o]) for c, o in pairs[:3]])

rng = np.random.default_rng(0)
DIM, NEGATIVES, LR = 5, 3, 0.05
v = rng.normal(0, 0.5, (len(vocab), DIM))      # centre vectors: random at the start
u = rng.normal(0, 0.5, (len(vocab), DIM))      # neighbour vectors

# how often each word is picked as a fake: frequency to the power 0.75, as in Word2Vec
freq = np.bincount([o for _, o in pairs], minlength=len(vocab)) ** 0.75
noise = freq / freq.sum()

def sims(vectors):
    return {f"{a}/{b}": round(float(cosine(vectors[index[a]], vectors[index[b]])), 2)
            for a, b in [("pizza", "burger"), ("waiter", "waitress"), ("pizza", "waiter"), ("delicious", "rude")]}

print("before training:", sims(v))

for epoch in range(300):                       # one epoch = one pass over all pairs
    for c, o in rng.permutation(pairs):
        fakes = rng.choice(len(vocab), NEGATIVES, p=noise)            # step 3
        for target, label in [(o, 1)] + [(f, 0) for f in fakes]:
            p = sigmoid(v[c] @ u[target])                             # step 2
            error = p - label
            v_old = v[c].copy()
            v[c] -= LR * error * u[target]                            # step 4
            u[target] -= LR * error * v_old

print("after training :", sims(v))
```

The saved similarities start out random. After 300 passes through the pairs, `pizza`/`burger` and `waiter`/`waitress` are close to 1; `pizza`/`waiter` and `delicious`/`rude` are lower.

The training data never states the meaning of any word. The model only tries to separate real neighbor pairs from random pairs. Words with similar neighbors end up with similar vectors.

The hand-written Python loop processes one pair at a time, which is slow. The lecture describes gensim as a much faster implementation—about a million pairs per second—and uses it for the larger example.
