`as_vector` uses the same vocabulary order for every word. Position-by-position comparison only makes sense when each position refers to the same neighbor.

```python
vocab = sorted({w for s in toy for w in s})

def as_vector(word):
    return np.array([neighbours[word][n] for n in vocab])    # one number per possible neighbour

for a, b in [("pizza", "burger"), ("waiter", "waitress"), ("pizza", "waiter"), ("delicious", "cold")]:
    print(f"{a:9} {b:9} {cosine(as_vector(a), as_vector(b)):.2f}")
```


**Saved output:**

```text
pizza     burger    1.00
waiter    waitress  1.00
pizza     waiter    0.84
delicious cold      1.00
```



#### Read the similarities

- `pizza`/`burger` and `waiter`/`waitress` score **1.00**. Matching contexts have produced matching vectors without anyone supplying “food” or “staff” labels.
- `pizza`/`waiter` scores **0.84**, also quite high. Both often occur near *the* and *was*, so very common neighbors make different words look similar.
- `delicious`/`cold` scores **1.00**. They can both fill the blank in *the pizza was ___*. This is a limitation: words with opposite meanings can occur in the same contexts and get similar vectors.

A full neighbor-count vector would have one value for every vocabulary word—often tens of thousands, mostly zero. The lecture next uses Word2Vec to learn a much smaller representation, later using 100 numbers per word.
