# Part 6. One recipe, many models

Look back at the models of this course. They differ in only two places: what happens to the
weighted sum, and which loss is used.

| model | weighted sum | then | output | loss | trained by |
|---|---|---|---|---|---|
| linear regression | $z = w \cdot x + b$ | nothing | any number (minutes, stars) | MSE | formula, or gradient descent |
| logistic regression (week 5) | $z = w \cdot x + b$ | **sigmoid** $\frac{1}{1 + e^{-z}}$ | probability between 0 and 1 | log loss | gradient descent |
| multi-class logistic regression | one $z$ per class | **softmax** | one probability per class, adding up to 1 | log loss | gradient descent |

(**Softmax** does for several classes what the sigmoid does for two: it turns a list of scores into
probabilities that are all positive and add up to 1. It returns in later weeks.)

And the gradient descent step is the same idea every time: **error times input**. For linear
regression you saw it in Part 4.2. For logistic regression in week 5 it was
$(\text{prediction} - \text{truth}) \times \text{feature}$.

This table is the map for the rest of the course. A **neural network** keeps every column: weighted
sums, a function applied to them, a loss, gradient descent. What it adds is a *chain* of weighted
sums, where the outputs of one become the inputs of the next.

The same 3-step code works for any of these models in `sklearn`:

```python
from sklearn.linear_model import LogisticRegression

stars_classifier = LogisticRegression(max_iter=2000).fit(T_train, y_train_df["stars"])
probs = stars_classifier.predict_proba(tfidf.transform(mine))

print("classes:", stars_classifier.classes_)
for text, p in zip(mine, probs):
    print(f"{p.round(2)}  -> {stars_classifier.classes_[p.argmax()]} stars   {text}")
```

**Saved output:**

```text
classes: [1 2 3 4 5]
[0.   0.   0.   0.01 0.99]  -> 5 stars   absolutely amazing, best pizza in town
[0.02 0.63 0.35 0.   0.  ]  -> 2 stars   the food was ok but the service was slow
[0.96 0.03 0.   0.   0.01]  -> 1 stars   never again. rude staff
[0.87 0.11 0.02 0.   0.  ]  -> 1 stars   not bad at all
```

Here the star rating is treated as **classification**: five classes, one probability each (they add
up to 1 in each row). `not bad at all` gets its highest probability for 1 star, the same mistake as
the regression model, for the same reason.

Is a star rating a number or a category? Both views are possible, and they make different mistakes.
Notebook 11 measures which one works better, and learns how to measure a model properly.

# Recap

- **Machine learning** finds the rules from labelled **examples** instead of a person writing them.
  Inputs are **features**, correct answers are **labels**; **classification** predicts categories,
  **regression** predicts numbers.
- Data is a table $X$ (examples × features) and a vector $y$.
- A **model** is a formula with **parameters**. Linear regression: $\hat{y} = w \cdot x + b$, a
  weighted sum - a **dot product** plus a **bias**.
- A **loss** measures how wrong the parameters are as one number: **MSE** for training, **MAE**
  for reporting in real units.
- The loss as a function of the parameters is a bowl. Its **slope** (derivative) says which way is
  downhill. **Gradient descent** steps against the slope, with step size = **learning rate**.
  Too small: slow. Too large: **divergence**. The learning rate is a **hyperparameter**.
- The slope for each weight is **error × input**, averaged. The same pattern trains logistic
  regression and neural networks.
- Always compare with a **baseline**. On Yelp: baseline 1.17 stars off, four hand features 0.97,
  one weight per word 0.73.
- A linear model adds up evidence; it cannot express "`not` reverses the next word", and it does
  not know that ratings stop at 5.
