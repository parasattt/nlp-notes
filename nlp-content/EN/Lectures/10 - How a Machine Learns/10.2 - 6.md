# Part 2. Data is a table of numbers

Every ML library expects the same two objects:

- $X$, the **feature matrix**: one **row** per example, one **column** per feature
- $y$, the **label vector**: one number per example (a **vector** is just a list of numbers)

Text must first be turned into numbers. Here are four support tickets, described by three features
we choose ourselves:

```python
tickets = pd.DataFrame({
    "ticket": ["Where is my order???",
               "Charged twice, refund NOW!!!",
               "Thanks, all good",
               "The screen arrived cracked, I want a refund"],
    "minutes_to_resolve": [6, 25, 1, 30],
})

def ticket_features(text):
    words = re.findall(r"[a-z]+", text.lower())
    return [len(words), text.count("!") + text.count("?"), int("refund" in words)]

X_small = np.array([ticket_features(t) for t in tickets["ticket"]])
y_small = tickets["minutes_to_resolve"].to_numpy()

print("feature columns: [number of words, number of ! and ?, mentions refund]")
print("X =\n", X_small)
print("y =", y_small)
print("shape of X:", X_small.shape, "  shape of y:", y_small.shape)
```

**Saved output:**

```text
feature columns: [number of words, number of ! and ?, mentions refund]
X =
 [[4 3 0]
 [4 3 1]
 [3 0 0]
 [8 0 1]]
y = [ 6 25  1 30]
shape of X: (4, 3)   shape of y: (4,)
```

The **shape** (4, 3) means 4 rows (tickets) and 3 columns (features). The label here is a number -
minutes the support team needed - so predicting it is a regression problem.

The choice of features is ours, and it matters more than almost anything else. Week 4's bag of
words used one column per vocabulary word, so $X$ had thousands of columns, but it is still this
same table. The model never sees the text, only $X$.
