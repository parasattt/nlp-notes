The large-data setups compare NB + counts, LR + TF-IDF, and LR with TF-IDF unigrams and bigrams. In the bigram vectorizer, `min_df=2` requires a feature to occur in at least two training documents, and `sublinear_tf=True` reduces the effect of repeated term counts. The source loop tests each listed training size on the same held-out test set.

```python
big_setups = {
    "NB + counts": make_pipeline(CountVectorizer(), MultinomialNB()),
    "LR + tf-idf": make_pipeline(TfidfVectorizer(), LogisticRegression(max_iter=2000)),
    "LR + tf-idf, bigrams": make_pipeline(
        TfidfVectorizer(ngram_range=(1, 2), min_df=2, sublinear_tf=True),
        LogisticRegression(max_iter=2000)),
}
big_sizes = [96, 250, 500, 1000, 2000, 5000, 10000, 20000]

big_curves = {name: [] for name in big_setups}
```

The saved chart and original discussion describe the following large-data pattern. These are **stored results and source interpretation**, not a newly verified run after the preceding errors:

- At 96 training reviews, NB is ahead: 0.687 versus 0.616, about seven percentage points.
- The lines cross at around 500 reviews.
- At 20,000 training reviews, LR + TF-IDF reaches 0.876 against NB's 0.839. LR with bigrams reaches 0.886. The source describes this as almost four points for LR and almost five with bigrams.
- With 5,000 test reviews, one review changes accuracy by 0.02 percentage points. The 0.037 NB/LR gap is roughly 180 reviews, much larger than a single changed prediction.
- From 10,000 to 20,000 reviews, the source reports only a 0.2-point gain for NB, while LR is still improving.

The notebook connects this pattern to its earlier Ng and Jordan (2002) discussion: NB learns quickly from little data; LR can improve further with enough data. Which performs better depends on the training size in these examples. Bigrams that did not help on 120 reviews can help at scale because phrases such as `not good` finally occur often enough to learn useful weights.
