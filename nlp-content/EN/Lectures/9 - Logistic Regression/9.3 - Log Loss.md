## Measure probability errors with log loss

To learn weights, the model needs a number describing how wrong its current probabilities are. The source uses **log loss**:

$$\text{loss} = -\log(\text{probability the model gave to the correct answer})$$

First take the probability assigned to the true class, then take its natural log, then change the sign. A larger probability for the correct answer means a smaller loss. A very small probability for the correct answer means a large loss.

Think of a forecaster who says “99% sun” and is wrong when it rains. That forecast is worse than saying “50/50” before the same rain. Both may lead to a wrong label, but only the first is confidently wrong. Log loss captures that difference. The next saved table shows the exact penalty at a range of correct-class probabilities.



```python
for p_correct in [0.99, 0.9, 0.6, 0.5, 0.1, 0.01, 0.001, 0.0001, 0.00001, 0.000001, 0.0000001]:
    print(f"gave the correct class {p_correct:4} -> loss {-np.log(p_correct):.3f}")
```


**Saved output:**

```text
gave the correct class 0.99 -> loss 0.010
gave the correct class  0.9 -> loss 0.105
gave the correct class  0.6 -> loss 0.511
gave the correct class  0.5 -> loss 0.693
gave the correct class  0.1 -> loss 2.303
gave the correct class 0.01 -> loss 4.605
gave the correct class 0.001 -> loss 6.908
gave the correct class 0.0001 -> loss 9.210
gave the correct class 1e-05 -> loss 11.513
gave the correct class 1e-06 -> loss 13.816
gave the correct class 1e-07 -> loss 16.118
```



A correct-class probability of 0.99 costs only 0.010 loss. At 0.5, the loss is 0.693. At 0.01, it rises to 4.605: this is the confidently wrong “99% sun” forecast when rain occurs. The stored table continues down to `1e-07`, where the loss is 16.118.

Log loss therefore evaluates the confidence as well as whether the winning class is correct. Learning will adjust the weights to reduce the **average** loss across training examples.
