## Compare models with cross-validation

One train/test split is only one choice of which examples are seen during training. Lecture 7 showed that [[EN/Lectures/7 - Naive Bayes Classification/7.12 - Split Stability and Vocabulary Coverage|changing that choice can change the score]]. This comparison therefore uses **five-fold cross-validation**:

1. Divide the 120 reviews into five parts, keeping class proportions balanced with `StratifiedKFold`.
2. Fit a fresh pipeline on four parts and evaluate on the fifth.
3. Repeat until each part has served as the unseen test part once.
4. Average the five scores to get one result for that shuffle.
5. Repeat the whole five-fold process for five different shuffles, using seeds 0 through 4.

Because the vectorizer is inside each pipeline, it is fitted again using only that fold's training text. This prevents test-fold vocabulary and IDF values leaking into training.

The five setups vary both the classifier and representation: NB with counts, NB with TF-IDF, LR with counts, LR with TF-IDF, and LR with TF-IDF unigrams plus bigrams.



`ngram_range=(1, 2)` adds bigrams to unigrams in the fifth setup. Each item in `per_shuffle` is already the average of five held-out fold scores; the printed mean then averages across the five shuffles.

```python
setups = {
    "NB  + counts": make_pipeline(CountVectorizer(), MultinomialNB()),
    "NB  + tf-idf": make_pipeline(TfidfVectorizer(), MultinomialNB()),
    "LR  + counts": make_pipeline(CountVectorizer(), LogisticRegression(max_iter=2000)),
    "LR  + tf-idf": make_pipeline(TfidfVectorizer(), LogisticRegression(max_iter=2000)),
    "LR  + tf-idf, bigrams": make_pipeline(TfidfVectorizer(ngram_range=(1, 2)),
                                            LogisticRegression(max_iter=2000)),
}

results = {}
for name, pipe in setups.items():
    per_shuffle = [
        cross_val_score(pipe, reviews, review_labels,
                        cv=StratifiedKFold(5, shuffle=True, random_state=s)).mean()
        for s in range(5)
    ]
    results[name] = per_shuffle
    print(f"{name:22}  mean {np.mean(per_shuffle):.3f}   per shuffle {np.round(per_shuffle, 3)}")
```


**Saved output:**

```text
NB  + counts            mean 0.658   per shuffle [0.692 0.658 0.633 0.633 0.675]
NB  + tf-idf            mean 0.655   per shuffle [0.692 0.658 0.617 0.633 0.675]
LR  + counts            mean 0.625   per shuffle [0.633 0.625 0.65  0.592 0.625]
LR  + tf-idf            mean 0.648   per shuffle [0.683 0.642 0.642 0.608 0.667]
LR  + tf-idf, bigrams   mean 0.647   per shuffle [0.667 0.642 0.65  0.608 0.667]
```



The saved means range from about 0.63 to 0.66. **Naive Bayes with raw counts has the highest mean**, 0.658. LR with TF-IDF has mean 0.648, about one percentage point lower, and adding bigrams gives 0.647 rather than an improvement.

Compare those differences with the changes caused by shuffling. LR with TF-IDF ranges from 0.608 to 0.683: 7.5 percentage points with the same model and data. The best models' mean gaps are smaller than that variation. These results do not establish a reliable winner on just 120 reviews; if anything, the stored means put Naive Bayes slightly ahead.

The source also reports LR scoring 1.00 on the earlier spam set, matching Naive Bayes. That task is too easy to distinguish them. A perfect score there does not settle this comparison.
