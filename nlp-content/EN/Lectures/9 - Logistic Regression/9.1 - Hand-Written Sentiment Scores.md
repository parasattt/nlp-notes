A support team lead has 300 new reviews but can read only 40. A positive/negative label leaves many reviews tied. The useful question is: **which 40 reviews should be read first?**

We need a number for each review: how likely it is to be a complaint. Then the team can sort the reviews and start at the top. Logistic regression produces that probability.

This lecture builds the model from scratch, compares it with `sklearn`, and chooses a decision threshold for support work. It also compares logistic regression with Naive Bayes on the teaching reviews and on 20,000 real reviews.

The same ideas will be used again for neural networks in the syllabus: weighted inputs, a bias, a squashing function, a loss, and learned weights. The full 120-review corpus below is the same as in Lecture 8.

This builds on [[EN/Lectures/7 - Naive Bayes Classification/7.11 - Reusing the Pipeline for Sentiment|the sentiment classifier]] and [[EN/Lectures/8 - TF-IDF and Text Search/8.5 - TF-IDF by Hand|TF-IDF features]].

## Start with weights chosen by hand

Give sentiment words positive or negative weights. For each review, add the weights of its words and look at the sign of the score. This is a simple first version of the weighted-sum calculation that logistic regression will later learn from data.



`hand_score` lowercases a review, extracts word-like pieces with the shown regex, and sums dictionary weights. Unlisted words contribute zero. The printed scores make the rule failures visible.

```python
WEIGHTS = {
    "great": 2, "excellent": 2, "perfect": 2, "love": 2, "happy": 1.5,
    "good": 1, "recommend": 1,
    "broke": -2, "terrible": -2, "waste": -2, "disappointed": -2,
    "poor": -1.5, "cheap": -1, "not": -1,
}

def hand_score(text):
    return sum(WEIGHTS.get(w, 0) for w in re.findall(r"\w+", text.lower()))

for t in [
    "excellent product works perfectly very happy with this purchase",
    "terrible quality broke after two days waste of money",
    "Not good. The screen flickers constantly.",
    "Not bad at all for the price, I'm pleasantly surprised :)",
    "Returned it the next day.",
]:
    print(f"{hand_score(t):5}  {t}")
```


**Saved output:**

```text
  3.5  excellent product works perfectly very happy with this purchase
   -6  terrible quality broke after two days waste of money
    0  Not good. The screen flickers constantly.
   -1  Not bad at all for the price, I'm pleasantly surprised :)
    0  Returned it the next day.
```



The first two saved scores fit their reviews: `3.5` for obvious praise and `-6` for an obvious complaint. The next three reveal different problems:

- `Not good. The screen flickers constantly.` scores 0 because `not` contributes -1 and `good` contributes +1, cancelling each other.
- `Not bad at all ...` is positive but scores -1. `bad` is absent from the weight dictionary, while `not` contributes a negative weight.
- `Returned it the next day.` has no selected word, so it also scores 0.

The next cell checks how many reviews have a zero hand-written score.



```python
scores = [hand_score(r) for r in reviews]

print("reviews containing no weighted word:", sum(s == 0 for s in scores), "of", len(reviews))
```


**Saved output:**

```text
reviews containing no weighted word: 66 of 120
```



The saved count is 66 zero scores out of 120 reviews, more than half. The printed label calls these reviews “containing no weighted word,” but the code tests `s == 0`; as `not good` shows, selected words can also cancel to zero.

Hand-picked weights do not scale well. There are too many words, and it is difficult to guess a useful weight for something like `returned` or `after`.

The model's basic shape is still useful: multiply features by weights and add. Logistic regression keeps that shape and adds two things: a function that turns a score into a probability, and a method that learns the weights from labelled examples.
