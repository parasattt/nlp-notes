## Compare confidence as well as accuracy

If the accuracy scores are close on small data, what else might matter? A support team acts on probabilities, so the confidence of mistakes matters too.

`cross_val_predict(..., method="predict_proba")` gives each review a probability from a model trained without that review's fold. The next code counts wrong predictions and asks how many of those wrong predictions were made with more than 90% confidence.



```python
from sklearn.model_selection import cross_val_predict

cv5 = StratifiedKFold(5, shuffle=True, random_state=0)
y_all = np.array(review_labels)

for name in ["NB  + counts", "LR  + tf-idf"]:
    proba = cross_val_predict(setups[name], reviews, y_all, cv=cv5, method="predict_proba")
    pred = np.array(["negative", "positive"])[proba.argmax(axis=1)]
    conf = proba.max(axis=1)
    wrong = pred != y_all

    print(name)
    print(f"  wrong predictions               : {wrong.sum()}")
    print(f"  ...of which made with >90% conf.: {(conf[wrong] > 0.9).sum()}")
    print(f"  confidence range                : {conf.min():.2f} to {conf.max():.2f}")
    print()
```


**Saved output:**

```text
NB  + counts
  wrong predictions               : 37
  ...of which made with >90% conf.: 9
  confidence range                : 0.50 to 1.00

LR  + tf-idf
  wrong predictions               : 38
  ...of which made with >90% conf.: 0
  confidence range                : 0.50 to 0.70

```



The saved NB pipeline makes 37 mistakes; 9 of them have confidence above 90%. LR makes 38 mistakes, but none above 90%; its confidence only ranges from 0.50 to 0.70.

For the support team, an angry complaint incorrectly scored as 0.99 positive could sink to the bottom of the reading list. Similar accuracy does not mean equally useful confidence.

The source connects Naive Bayes overconfidence to its independence assumption. Several overlapping sentiment words are multiplied as if each were independent evidence, which can push the result toward an extreme probability. The next direct test repeats one word to make this effect visible.



Both demonstration pipelines are fitted on the full teaching corpus for this controlled repetition test. The code prints the negative-class probability for one occurrence of `broke` and for four occurrences.

```python
nb_fit = make_pipeline(CountVectorizer(), MultinomialNB()).fit(reviews, review_labels)
lr_fit = make_pipeline(TfidfVectorizer(), LogisticRegression(max_iter=2000)).fit(reviews, review_labels)

for t in ["broke", "broke broke broke broke"]:
    print(f"{t:26} NB P(negative)={nb_fit.predict_proba([t])[0, 0]:.3f}   "
          f"LR P(negative)={lr_fit.predict_proba([t])[0, 0]:.3f}")
```


**Saved output:**

```text
broke                      NB P(negative)=0.789   LR P(negative)=0.642
broke broke broke broke    NB P(negative)=0.995   LR P(negative)=0.642
```



Repeating `broke` four times changes the saved NB negative probability from 0.789 to 0.995. With count features, it counts that evidence four times. The LR + TF-IDF pipeline stays at 0.642 because normalisation makes these two inputs the same vector.

This comparison changes both model and representation. The unchanged LR result here comes specifically from TF-IDF normalisation; it is not a claim that every LR input representation ignores repetition.

On this small corpus, LR's probabilities are cautious, rather than proven perfectly calibrated. The regularisation setting later will show how that caution can change.
