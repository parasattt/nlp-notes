## Multiply term frequency by IDF

`the` gets zero because $\log(3/3) = 0$. `battery` gets about `0.405`, from `log(3/2)`. A word found in only one document gets about `1.099`, from `log(3/1)`.

Here **term frequency** (TF) means a word's raw count within one document. **TF-IDF** multiplies that local count by the word's corpus-wide IDF:

$$\text{tfidf}(w, d) = \text{count}(w, d) \times \text{idf}(w)$$

`w` is the word and `d` is the document. `count(w, d)` tells us how often the word is used in this document; `idf(w)` tells us how distinctive it is across the collection. Multiplying them gives a feature value that uses both kinds of information.

The code multiplies each vocabulary column of `counts` by its matching IDF. For example, the second document has two `is` tokens, so its `is` feature becomes `2 × 1.099 ≈ 2.197`.



Multiplying `counts * idf_naive` applies one IDF value to each word column across all document rows. This is the unnormalised textbook calculation, kept separate from the library defaults.

```python
tfidf_naive = counts * idf_naive

print(pd.DataFrame(tfidf_naive, columns=vocab).round(3))
```

Every `the` count is multiplied by zero, so `the` disappears from the textbook TF-IDF rows. Distinctive words such as `died`, `after`, `week`, `sharp`, and `delivery` now carry more weight.

There is an important limitation: row 1 gives the largest value to **`is`**, at 2.197. It occurs twice and happens to appear in just one of these three documents. IDF therefore treats it as rare, although it is common in ordinary English.

IDF only knows the corpus used to calculate it. Its judgement of rarity can be misleading on a tiny collection. Later, using all 120 reviews puts `is` near the low-IDF end where the notebook expects it.
