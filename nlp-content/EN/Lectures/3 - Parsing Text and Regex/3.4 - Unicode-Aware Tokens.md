```python
# \w is shorthand for "word character": letters, digits, underscore.
# It also covers Cyrillic, Kazakh, Chinese - anything Unicode considers a letter.
print(re.findall(r"\w+", "Привет, мир! Сәлем, әлем! Hello, world!"))
```


**Saved output:**

```text
['Привет', 'мир', 'Сәлем', 'әлем', 'Hello', 'world']
```



The ASCII letter pattern silently fails on Kazakh or Russian: it returns no tokens and raises no error. A pipeline could continue with zero word counts.

Python 3's `\w+` is Unicode-aware by default. It can match the Cyrillic examples shown above, so the lecture recommends it over an English-only character range for this case.

## Token choices affect the whole pipeline

The functions above are **tokenizers**. Their decisions are passed to every later step:

- Is `don't` one token, or `do` plus `n't`?
- Is `New York` one unit or two?
- Is `#nlp2026` one hashtag, or a word and a number?
- Are numbers, emoji, and URLs kept?

Libraries such as NLTK and spaCy provide tokenizers with many of these choices already built in. They still make choices, so understanding the underlying rules helps you judge whether they fit your data.

The tokenizer comparison in [[EN/Lectures/4 - Tokenization/4.3 - Comparing NLTK Word Tokenizers|real tokenizers]] develops these choices with library implementations.
