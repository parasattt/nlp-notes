## When another tool is better

- **Nested structures:** HTML, JSON, XML, and source code need parsers that understand structure. The lecture recommends BeautifulSoup, `json.loads`, or an appropriate parser rather than a regex that cannot track arbitrary nesting.
- **Production sentence/word splitting:** established tools such as spaCy and NLTK already handle many edge cases.
- **Simple string questions:** `"x" in text` is clearer than `re.search(r"x", text)` when substring membership is all that is needed.
- **Unreadable patterns:** if a pattern needs a long explanation just to be maintained, consider a small function instead. Code will be read repeatedly.

Regex works well for **flat, local patterns** such as a date, URL, token, or log field. Nested structure requires a different approach.
