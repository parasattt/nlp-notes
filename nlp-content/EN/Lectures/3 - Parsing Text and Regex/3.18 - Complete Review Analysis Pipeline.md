## Put the whole workflow together

The following example combines the first four notebooks in a practical order. The source offers it as a template for future assignments: preserve raw signals, clean, tokenize, analyze, and check whether the observations are supported.



```python
corpus = [
    ("<p>Absolutely LOVE this laptop!! Fast, quiet, great screen. https://shop.kz/l/99</p>", 5),
    ("Broke after 3 weeks. Support ignored my emails at help@shop.kz. Terrible.", 1),
    ("Decent phone for the price. Camera is OK, battery could be better.", 3),
    ("<b>WORST PURCHASE EVER</b> Do not buy!!! Overheats, crashes, useless.", 1),
    ("Great value. Arrived 2026-02-14, well packaged, works perfectly.", 5),
    ("It is fine I guess. Nothing special. 3/5.", 3),
    ("Beautiful display and excellent build quality. Very happy!", 5),
    ("Stopped charging within a month. Avoid this seller. Call +7 701 555 0199.", 1),
]

df = pd.DataFrame(corpus, columns=["raw", "rating"])

df.head(3)
```

```python
# --- Step 1: features that must be taken from the RAW text ---
df["n_exclaim"]   = df["raw"].str.count(r"!")
```

```python
# --- Step 2: clean ---
def clean(t):
    t = re.sub(r"<[^>]+>", " ", t)
    t = re.sub(r"https?://\S+", " <url> ", t)
    t = re.sub(r"\S+@\S+\.\S+", " <email> ", t)
    t = re.sub(r"\d{4}-\d{2}-\d{2}", " <date> ", t)     # specific before general
    t = re.sub(r"\+?\d[\d\s\-()]{7,}\d", " <phone> ", t)
    t = t.lower()
    t = re.sub(r"\s+", " ", t)
    return t.strip()

df["clean"] = df["raw"].apply(clean)
df[["raw", "clean"]].head(4)
```

```python
# --- Step 3: tokenize ---
STOP = {"the","a","an","is","was","are","were","in","on","at","to","for","of",
        "and","but","or","it","this","that","i","my","me","you","be","so","very",
        "url","email","phone","date"}

def tokenize(t):
    tokens = re.findall(r"[a-z]+", t)
    return [w for w in tokens if w not in STOP and len(w) > 2]

df["tokens"] = df["clean"].apply(tokenize)
df["n_tokens"] = df["tokens"].str.len()
df[["clean", "tokens"]].head(4)
```

```python
# --- Step 4: analyse ---
#print(df)
df["sentiment"] = df["rating"].apply(lambda r: "positive" if r >= 4 else ("negative" if r <= 2 else "neutral"))

pos_words = [w for row in df.loc[df["sentiment"] == "positive", "tokens"] for w in row]
neg_words = [w for row in df.loc[df["sentiment"] == "negative", "tokens"] for w in row]

print("Top words in POSITIVE reviews:")
for w, n in Counter(pos_words).most_common(8):
    print(f"   {w:<12} {n}")

print("\nTop words in NEGATIVE reviews:")
for w, n in Counter(neg_words).most_common(8):
    print(f"   {w:<12} {n}")
```

The label assignment uses [[EN/Lectures/1 - Python Basics for Text/1.13 - Conditions and Keyword Sentiment|conditional expressions and sentiment rules]]; the row selection uses [[EN/Lectures/2 - Pandas for Text Data/2.19 - Label and Position Indexing|label-based selection with loc]].



Treat these rankings cautiously. There are only eight reviews, and most words occur once. “Top eight” is then close to “the first eight words encountered,” rather than strong evidence about the classes.

The source mentions positive words such as *great*, *love*, and *excellent*, and negative words such as *broke*, *terrible*, and *worst*. With so few observations, both signal and noise affect the list.

The same method on ten thousand reviews could be much more informative. Distinguish a sensible method from a sample too small to support a confident conclusion.



```python
# --- Step 5: do the non-text features carry signal? ---
df.groupby("sentiment")[["n_exclaim", "n_caps", "n_tokens", "char_len"]].mean().round(2)
#print(df["sentiment"])
```

```text
negative         1.0    1.00      7.33     71.67
neutral          0.0    0.50      5.00     53.50
positive         1.0    0.33      6.67     68.67
```



The saved group means show `n_caps` at 1.00 for negative reviews and 0.33 for positive reviews. This agrees with the idea that angry reviewers might use more capitals.

But the difference comes from **one review**, `WORST PURCHASE EVER`. Remove it and the pattern disappears. Three negative reviews are too few to establish a general rule. ^small-sample-warning

A careful conclusion is “this could be a useful feature to test on real data,” not “negative reviews use more capitals.” The lecture encourages writing the first kind of claim rather than treating a small example as proof.

The workflow still shows the main process: turn messy raw text into structured numbers, then ask a question precisely enough to test. Vectorization, classifiers, embeddings, and transformers depend on this preparation.
