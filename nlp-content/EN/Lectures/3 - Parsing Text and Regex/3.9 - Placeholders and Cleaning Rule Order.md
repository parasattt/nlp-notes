## Replace variable details with placeholders

An NLP model may not benefit from memorizing thousands of different URLs. But the fact that **a URL was present** can be useful, especially for spam detection.

Replace details such as URLs, emails, phone numbers, and dates with placeholder tokens. This keeps their type while reducing the number of different strings.



```python
post = """Check out https://example.com/deals for 50% off!
Contact us at sales@example.com or support@shop.kz.
Call +7 701 555 0199. Order #12345 shipped 2026-03-15."""

clean = post
clean = re.sub(r"https?://\S+", " <URL> ", clean)
clean = re.sub(r"\S+@\S+\.\S+", " <EMAIL> ", clean)
clean = re.sub(r"\+?\d[\d\s\-()]{7,}\d", " <PHONE> ", clean)
clean = re.sub(r"\d{4}-\d{2}-\d{2}", " <DATE> ", clean)
clean = re.sub(r"\s+", " ", clean).strip()

print(clean)
```


**Saved output:**

```text
Check out <URL> for 50% off! Contact us at <EMAIL> or <EMAIL> Call <PHONE> . Order #12345 shipped <PHONE> .
```



### Read the URL pattern piece by piece

For `https?://\S+`:

- `http` matches those literal letters.
- `s?` makes the `s` optional, allowing HTTP and HTTPS.
- `://` is literal text.
- `\S+` matches the following run of non-whitespace characters.

The source asks you to compare this with a `find()`/slicing solution: a manual version would need more code and could miss a URL at the end of a line.

### Find the cleaning-order bug

The saved output turns the date `2026-03-15` into `<PHONE>`, rather than `<DATE>`.

The phone pattern `\+?\d[\d\s\-()]{7,}\d` accepts an optional plus, a digit, at least seven digit/space/dash/bracket characters, and a final digit. The date fits that shape.

The phone rule runs first and consumes the date. When the date rule runs, the original date is already gone.

A general rule before a specific rule can therefore produce plausible-looking but wrong text without raising an error. The repair is to apply the more specific rule first.



```python
clean = post
clean = re.sub(r"https?://\S+", " <URL> ", clean)          # URLs first (they contain @ and digits)
clean = re.sub(r"\S+@\S+\.\S+", " <EMAIL> ", clean)        # then emails
clean = re.sub(r"\d{4}-\d{2}-\d{2}", " <DATE> ", clean)     # dates BEFORE phones - specific first
clean = re.sub(r"\+?\d[\d\s\-()]{7,}\d", " <PHONE> ", clean)
clean = re.sub(r"\s+", " ", clean).strip()

print(clean)
```


**Saved output:**

```text
Check out <URL> for 50% off! Contact us at <EMAIL> or <EMAIL> Call <PHONE> . Order #12345 shipped <DATE> .
```



The corrected saved output keeps the date as `<DATE>`.

Apply **specific patterns first, general patterns last**. Handle URLs before emails because a URL can contain `@`. Handle dates before phone numbers because a date can resemble a phone number. Put a catch-all such as `\d+` last, if it is needed. ^specific-before-general

Cleaning is a sequence of steps: every replacement changes the text that the following step receives.
