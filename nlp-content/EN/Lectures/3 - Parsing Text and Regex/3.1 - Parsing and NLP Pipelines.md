## Parsing Text and Regular Expressions

For each problem, the lecture follows the same learning process:

1. Use ordinary Python to solve it.
2. Try realistic text and see where that solution fails.
3. Solve it again with a regular expression.

The aim is to understand why regex is useful, not to treat it as magic. A tool is easier to use well when you have seen the problem it solves. Throughout the examples, keep asking: **how does this help an NLP pipeline?**



## Why parsing takes so much work

A simple description of NLP is “load data, call `model.fit()`, read the accuracy.” In practice, much of the work happens before fitting: getting text out of its original format and making it consistent.

Later methods—including bag of words, TF-IDF, word embeddings, and transformers—depend on how text is divided into **tokens**. Making a token sequence from raw text is **tokenization**.

Real input can contain HTML, inconsistent spaces, punctuation, mixed case, URLs, emails, phone numbers, several date formats, and encoding problems. This lecture shows how to handle those issues efficiently before modeling.
