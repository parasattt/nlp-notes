## Start with whitespace splitting

The first task is to turn a sentence into a list of words. For a clean sentence, a whitespace split looks sufficient.



```python
text = "Natural language processing is useful"
print(text.split())
```


**Saved output:**

```text
['Natural', 'language', 'processing', 'is', 'useful']
```



The clean example works. Now try text with punctuation, a contraction, quotation marks, and a title abbreviation.



```python
real = "Dr. Smith said: \"NLP is hard, isn't it?\" -- he wasn't wrong!"
print(real.split())
```


**Saved output:**

```text
['Dr.', 'Smith', 'said:', '"NLP', 'is', 'hard,', "isn't", 'it?"', '--', 'he', "wasn't", 'wrong!']
```



Look at the tokens in the saved result:

- `'said:'` still has a colon attached.
- `'"NLP'` still has its opening quotation mark.
- `'hard,'` would be counted separately from `'hard'`.
- `'it?"'` has two attached punctuation marks.
- `'--'` is treated as a word.

These are more than display problems. Splitting one word's occurrences across different tokens weakens word counts and the features built from them, which can hurt the later model.

### Try stripping punctuation

The next function removes a listed set of punctuation characters from each token's ends and lowercases the remaining text.



```python
def tokenize_v2(text):
    tokens = []
    for word in text.split():
        word = word.strip('.,!?;:"()[]{}-\'')
        if word:
            tokens.append(word.lower())
    return tokens

print(tokenize_v2(real))
```


**Saved output:**

```text
['dr', 'smith', 'said', 'nlp', 'is', 'hard', "isn't", 'it', 'he', "wasn't", 'wrong']
```

For the underlying string operations, see [[EN/Lectures/1 - Python Basics for Text/1.5 - String Cleaning and Whitespace|string cleaning methods]] and [[EN/Lectures/1 - Python Basics for Text/1.9 - Splitting and Joining Text|splitting and joining text]].



That improves the first example. Next, test text containing an email address, a phone number, a price, and a percentage.



```python
tricky = "Email me at ivan@mail.kz or call +7-701-555-0199. Cost: $19.99 (30% off!)"
print(tokenize_v2(tricky))
```


**Saved output:**

```text
['email', 'me', 'at', 'ivan@mail.kz', 'or', 'call', '+7-701-555-0199', 'cost', '$19.99', '30%', 'off']
```



The saved result is:

```text
['email', 'me', 'at', 'ivan@mail.kz', 'or', 'call',
 '+7-701-555-0199', 'cost', '$19.99', '30%', 'off']
```

The email, phone, and price are still **whole**. Whether that is useful depends on the task, but this tokenizer did not make that choice explicitly.

`strip()` removes characters only from the **ends** of a token. Punctuation in the middle survives because of its position, not because the program recognized an email or a price. The next examples move punctuation between the middle and the edges.



```python
print(tokenize_v2("Ready? (yes) -- the answer's 42."))
print(tokenize_v2("He said 'hello'."))
print(tokenize_v2("Rating: 4/5. Cost-benefit: good."))
```


**Saved output:**

```text
['ready', 'yes', 'the', "answer's", '42']
['he', 'said', 'hello']
['rating', '4/5', 'cost-benefit', 'good']
```



The same apostrophe is treated differently in two positions: it stays in `answer's`, but both surrounding apostrophes are removed from `'hello'`. Similarly, `4/5` stays together while `(yes)` loses its brackets.

Adding more characters to the strip list does not solve the underlying issue. The function grows, the reasons for its exceptions become harder to remember, and token behavior still depends on character position.

The approach describes **what to delete**. A more useful rule can describe **what a word should look like**.
