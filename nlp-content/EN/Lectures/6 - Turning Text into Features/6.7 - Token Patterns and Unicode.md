## token_pattern: regex decides what counts



Read the actual default regex before choosing a replacement.

```python
print(CountVectorizer().token_pattern)
```


**Saved output:**

```text
(?u)\b\w\w+\b
```



The default token pattern is a [[EN/Lectures/3 - Parsing Text and Regex/3.5 - Regex Syntax|regular expression]]. Its `\w\w+` part requires **two or more word characters**, and `\b` marks word boundaries. As a result, one-letter words such as `a` and `I` disappear. Single-letter variable names in mathematical text disappear too.



The short sentences expose the default minimum token length: both `I` and `a` are single characters.

```python
short_words = ["I need a car", "he needs a car too"]

v = CountVectorizer()
v.fit(short_words)
print(v.get_feature_names_out())
```


**Saved output:**

```text
['car' 'he' 'need' 'needs' 'too']
```



The saved vocabulary contains neither `I` nor `a`, and no error warns about their removal.

The notebook then revisits ASCII patterns and Kazakh text. Read the next code and its label carefully: they disagree.



The source code is kept exactly, including a misleading print label. The actual pattern in this call is Unicode-aware `r"\w+"`.

```python
kk = [
    "мен кітап оқыдым",
    "ол мектепке барды",
    "біз дүкеннен нан алдық",
]

# The tokenizing step first, on its own - exactly the week 1 demonstration.
print("what [a-zA-Z]+ finds:", re.findall(r"\w+", kk[0]))
```


**Saved output:**

```text
what [a-zA-Z]+ finds: ['мен', 'кітап', 'оқыдым']
```



**Source discrepancy:** the preceding print label says `what [a-zA-Z]+ finds`, and the source prose says it finds nothing. The code actually calls `re.findall(r"\w+", kk[0])`, which is Unicode-aware. Its saved output correctly contains `['мен', 'кітап', 'оқыдым']`.

The next cell really does pass the ASCII-only pattern `r"[a-zA-Z]+"` to `CountVectorizer`. That separate example raises an empty-vocabulary error.



This call really uses `[a-zA-Z]+`. The `try`/`except` catches its empty-vocabulary `ValueError` and prints the library’s message.

```python
try:
    ascii_only = CountVectorizer(token_pattern=r"[a-zA-Z]+")
    ascii_only.fit(kk)
except ValueError as e:
    print("ValueError:", e)
```


**Saved output:**

```text
ValueError: empty vocabulary; perhaps the documents only contain stop words
```



The explicit ASCII-only pattern cannot match these Cyrillic words, so `CountVectorizer` raises an error. Without an explicit failure, an empty representation could otherwise make every document look the same to a classifier.

The message suggests: `empty vocabulary; perhaps the documents only contain stop words`. The lecture stresses that this suggestion does not diagnose the actual cause here. It also states that the corpus contains no stop words. That claim is not needed to explain the error: this call did not enable a stop word filter at all. It failed because the regex could not match the alphabet.

Treat an error message's suggested cause as something to investigate. It reflects a common failure the library author expected, which may differ from your case.

The default pattern handles Unicode in these examples. The error was introduced by supplying the ASCII-only replacement. Compare [[EN/Lectures/4 - Tokenization/4.7 - Unicode and Cyrillic Text|the earlier Cyrillic tokenization demonstration]].



Using the default Unicode-aware pattern yields ten vocabulary words from the same Kazakh corpus.

```python
proper = CountVectorizer()
proper.fit(kk)

print("vocabulary:", proper.get_feature_names_out())
print("size:", len(proper.get_feature_names_out()))
print(proper)
```


**Saved output:**

```text
vocabulary: ['алдық' 'барды' 'біз' 'дүкеннен' 'кітап' 'мектепке' 'мен' 'нан' 'ол'
 'оқыдым']
size: 10
CountVectorizer()
```
