## Why sparse storage matters

A bag-of-words matrix contains mostly zeros because each document uses only a small part of the vocabulary. With a vocabulary of 50,000 words, a message containing 20 distinct words leaves 49,980 columns at zero.

In a **dense matrix**, memory is reserved for every cell, including every zero. A **sparse matrix** stores the nonzero values and their positions. SciPy uses this representation for `CountVectorizer` output.

Read the small example step by step:

1. `X.shape` is `(4, 22)`: four document rows and 22 word columns.
2. The total number of possible cells is `4 × 22 = 88`.
3. `X.nnz` is 24: only 24 entries are stored as nonzero.
4. The remaining `88 - 24 = 64` entries are zero.
5. In the printed coordinates, `(0, 4) 1` means document row 0 has a count of 1 in vocabulary column 4.

The following memory estimate shows why this becomes essential as the collection grows.



The code compares approximate dense and sparse memory under the source’s assumptions. It does not allocate either large matrix.

```python
n_docs, n_vocab = 50_000, 80_000

dense_gb = n_docs * n_vocab * 8 / 1024**3
sparse_gb = n_docs * 80 * 12 / 1024**3   # ~80 distinct words per document

print(f"dense  : {dense_gb:8.2f} GB")
print(f"sparse : {sparse_gb:8.4f} GB")
```


**Saved output:**

```text
dense  :    29.80 GB
sparse :   0.0447 GB
```



## Read the memory estimate

The code uses these quantities:

- `n_docs = 50_000`: the number of documents.
- `n_vocab = 80_000`: the number of vocabulary columns.
- `8`: the assumed bytes per stored dense value.
- `80`: the assumed number of distinct vocabulary words used per document.
- `12`: the code's approximate bytes per stored sparse entry, including its position.
- `1024**3`: the number of bytes used to convert the estimate to the printed GB units.

The dense estimate is:

$$\text{dense\_gb} = \frac{n_{docs}\,n_{vocab}\,8}{1024^3}$$

It allocates space for every document-word combination. The sparse estimate is:

$$\text{sparse\_gb} = \frac{n_{docs}\,80\,12}{1024^3}$$

It estimates storage for only about 80 nonzero entries per document. With the source's assumptions, the saved values are **29.80 GB dense** and **0.0447 GB sparse**. The sparse value is an estimate, not an exact measurement of every internal array.

The lecture describes 50,000 documents as a small corpus. Calling `.toarray()` is useful for inspecting these four messages, but it expands the matrix into dense storage and is a poor choice for real-sized data.
