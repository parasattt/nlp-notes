# Part 5. Choosing alpha without cheating

Part 4 chose the best alpha by looking at the **test** error. That is a mistake, and a common one.

The test set is supposed to stand for future, unseen data. Once we use it to *choose* something,
the chosen alpha is the one that happens to suit these particular 3 000 reviews, and the test MAE of
that choice is slightly too optimistic. Any use of test data during training or model selection is
called **data leakage**: information from the test set leaks into the model.

The fix: choose using a part of the **training** data only.

- **Validation set**: split the training set again. Train on one part, measure on the other (the
  validation set) to choose hyperparameters. Touch the test set once, at the very end.
- **Cross-validation (CV)**: do this several times. Split the training set into $k$ parts (**folds**),
  usually 5. Train on 4 folds and measure on the 5th; repeat so that each fold is the measuring fold
  once; average the 5 scores. Every training review is used for measuring exactly once, and the
  average is more stable than one split.

```
fold:     1      2      3      4      5
round 1: [test] train  train  train  train
round 2: train [test] train  train  train
...
round 5: train  train  train  train [test]
```

Inside each round the TF-IDF vocabulary must also be learned only from the 4 training folds;
otherwise words from the measuring fold leak in. A **pipeline** (week 5) does this automatically.

(This cell trains 25 models, about a minute.)

```python
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import cross_val_score, KFold

folds = KFold(5, shuffle=True, random_state=0)
cv_rows = []
for a in [0.1, 0.3, 1, 3, 10]:
    pipe = make_pipeline(TfidfVectorizer(min_df=2), Ridge(alpha=a))
    scores = -cross_val_score(pipe, y_train_df["text"], y_train_df["stars"], cv=folds,
                              scoring="neg_mean_absolute_error")
    cv_rows.append((a, scores.mean(), scores.std()))
    print(f"alpha {a:5}: CV MAE per fold {scores.round(3)}  mean {scores.mean():.3f}")

best_alpha = min(cv_rows, key=lambda r: r[1])[0]
print("\nchosen by cross-validation: alpha =", best_alpha)
```

Cross-validation picked alpha using training data only. Now, and only now, train on the whole
training set with that alpha and touch the test set once:

```python
final = make_pipeline(TfidfVectorizer(min_df=2), Ridge(alpha=best_alpha)).fit(y_train_df["text"], y_train_df["stars"])
print(f"final test MAE with alpha = {best_alpha}: {mae(final.predict(y_test_df['text']), y_test_df['stars']):.3f}")
```

**Saved output:**

```text
final test MAE with alpha = 1: 0.727
```

This number is an honest estimate of how the model will do on next month's reviews.

Here CV and the test set agree on roughly the same alpha, so the cheating in Part 4 cost little.
That is not always so: with small datasets, or when many settings are tried, choosing on the test
set can make a model look several points better than it is.

**Parameters vs hyperparameters**, once more: the weights are **parameters**, found by training.
`alpha`, `C`, the learning rate, `min_df`, the polynomial degree are **hyperparameters**, chosen by
you - with validation or cross-validation, never with the test set.
