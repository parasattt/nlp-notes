# Part 6. Measuring a classifier

For regression, MAE is a natural measure. For classification, the obvious one is **accuracy**: the
share of examples classified correctly. It is often not enough.

### 6.1 By hand: an urgent-ticket detector

A shop's model flags support tickets as **urgent** so a person reads them within 10 minutes. On 12
tickets:

```python
urgent = pd.DataFrame({
    "ticket": ["my card was charged 5 times, please stop it", "where is my order",
               "the charger is smoking", "thanks, all good", "how do I change my password",
               "someone else used my account", "the colour is a bit different",
               "I want to return the shoes", "URGENT!!! best price ever??",
               "delivery is late again", "the heater sparks when I turn it on", "do you sell gift cards?"],
    "truly_urgent":   [1, 0, 1, 0, 0, 1, 0, 0, 0, 0, 1, 0],
    "model_says":     [1, 0, 1, 0, 0, 0, 0, 0, 1, 1, 1, 0],
})
urgent
```

**Saved output:**

```text
                                         ticket  truly_urgent  model_says
0   my card was charged 5 times, please stop it             1           1
1                             where is my order             0           0
2                        the charger is smoking             1           1
3                              thanks, all good             0           0
4                   how do I change my password             0           0
5                  someone else used my account             1           0
6                 the colour is a bit different             0           0
7                    I want to return the shoes             0           0
8                   URGENT!!! best price ever??             0           1
9                        delivery is late again             0           1
10          the heater sparks when I turn it on             1           1
11                      do you sell gift cards?             0           0
```

Four outcomes are possible for each ticket. The names come from medicine: "positive" means the test
says *yes, urgent*.

| | model says urgent | model says not urgent |
|---|---|---|
| **truly urgent** | **TP** (true positive): caught | **FN** (false negative): missed |
| **not urgent** | **FP** (false positive): false alarm | **TN** (true negative): correctly ignored |

This 2 × 2 table is the **confusion matrix**. Count by hand:

- TP = 3 (charged 5 times, smoking charger, heater sparks)
- FN = 1 (*someone else used my account* - missed)
- FP = 2 (*URGENT!!! best price ever??* and *delivery is late again*)
- TN = 6

From these four numbers:

| measure | formula | here | question it answers |
|---|---|---|---|
| **accuracy** | (TP + TN) / all | 9 / 12 = **0.75** | how often is the model right? |
| **precision** | TP / (TP + FP) | 3 / 5 = **0.60** | when it raises an alarm, how often is it real? |
| **recall** | TP / (TP + FN) | 3 / 4 = **0.75** | of the real urgent tickets, how many did it catch? |
| **F1** | $2 \cdot \frac{P \cdot R}{P + R}$ | $2 \cdot \frac{0.6 \cdot 0.75}{1.35}$ = **0.67** | one number balancing precision and recall |

F1 is the **harmonic mean** of precision and recall: a kind of average that stays low if either of
the two is low. A model with precision 1.0 and recall 0.01 has F1 0.02, not 0.5.

```python
from sklearn.metrics import confusion_matrix, accuracy_score, precision_score, recall_score, f1_score

t, m = urgent["truly_urgent"], urgent["model_says"]
print("confusion matrix (rows = truth 0/1, columns = model 0/1):")
print(confusion_matrix(t, m))
print(f"accuracy  {accuracy_score(t, m):.2f}")
print(f"precision {precision_score(t, m):.2f}")
print(f"recall    {recall_score(t, m):.2f}")
print(f"F1        {f1_score(t, m):.2f}")
```

**Saved output:**

```text
confusion matrix (rows = truth 0/1, columns = model 0/1):
[[6 2]
 [1 3]]
accuracy  0.75
precision 0.60
recall    0.75
F1        0.67
```

Note how `sklearn` lays out the matrix: rows are the truth, columns the prediction, class 0 first.
So TN is top-left and TP bottom-right.

Which matters more depends on the cost of each mistake. A missed account hijack (FN) is far worse
than a person reading one extra ticket (FP), so this shop wants **high recall**, even at some cost in
precision. A spam filter is the opposite: putting a real email in spam (FP) is worse than letting one
spam through, so it wants **high precision**. Week 5's **threshold** is the dial between the two.
