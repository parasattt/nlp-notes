### Measure memory and response time

An autocomplete function runs while someone types, so it must answer quickly and fit in memory. `pickle.dumps` turns a Python object into bytes; the example uses the byte count as an estimate of the table's serialized size.



The code estimates serialized sizes with `pickle.dumps`, then repeats a suggestion 1,000 times to measure the small per-call cost. The displayed timings are stored measurements from the source.

```python
def mb(obj):
    return len(pickle.dumps(obj)) / 1e6

print(f"table for one word before : {mb(next_bi):6.1f} MB")
print(f"table for two words before: {mb(next_tri):6.1f} MB")

start = time.perf_counter()
for _ in range(1000):
    suggest("the food was")
print(f"one suggestion takes {(time.perf_counter() - start):.3f} ms")
```


**Saved output:**

```text
table for one word before :   10.3 MB
```


**Saved output:**

```text
table for two words before:   48.0 MB
one suggestion takes 0.008 ms
```



The saved suggestion time is a few thousandths of a millisecond. Memory is the larger issue in this experiment:

- One-word-context table: **10.3 MB**, with 35,639 different contexts.
- Two-word-context table: **48 MB**, with 935,935 different contexts.

Adding context creates many more entries. Since the editor displays four suggestions, the next helper keeps only the four most common next words for each context.



`keep_top` makes new dictionaries containing only each row’s `k` most common continuations. It is a storage experiment; the probability-total caveat in the next paragraph still applies.

```python
def keep_top(table, k=4):
    return {start: Counter(dict(counter.most_common(k))) for start, counter in table.items()}

print(f"two words before, top 4 only: {mb(keep_top(next_tri)):6.1f} MB")
print(f"one word before,  top 4 only: {mb(keep_top(next_bi)):6.1f} MB")
```


**Saved output:**

```text
two words before, top 4 only:   36.1 MB
one word before,  top 4 only:    1.7 MB
```



Keeping only the top four reduces the one-word-context table from **10.3 to 1.7 MB**, about sixfold. The two-word-context table falls from **48.0 to 36.1 MB**, a smaller saving.

Why? There are 2,897,333 triples across 935,935 contexts—about three next words per context on average. A top-four limit therefore removes few entries. Most space is used by the many distinct contexts.

There is also a probability detail: after trimming, `suggest` would divide by the total of the retained counts only. The order of suggestions stays the same, but displayed probabilities would change. Keep the original row totals if percentages are needed.
