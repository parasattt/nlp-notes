## Two problems with direct multiplication

The hand-written classifier shows the basic idea, but two problems make this direct version unreliable: a zero likelihood can erase all the evidence, and long products can become too small for the computer to store.



### A zero likelihood erases the other words



```python
classify_by_hand("free money tomorrow")
```


**Saved output:**

```text
message   : free money tomorrow
spam score: 0.0000000000
ham score : 0.0000000000
verdict   : ham

```



Both scores are zero, so the printed `ham` verdict is not useful. The code uses `>`; when both scores tie at zero, it chooses the `else` branch.

`tomorrow` did not occur in the spam training messages, so $P(\text{tomorrow} \mid \text{spam}) = 0$. Multiplying by that zero erases the evidence from `free` and `money`. Ham has its own zero likelihoods for those words, so it also gets a zero score.

A finite training collection cannot show every word in every class. This problem will happen regularly, so we need to treat “not seen in this class” as different from “impossible in this class.”



## Laplace smoothing

**Laplace smoothing**, also called additive smoothing, gives every vocabulary word a small extra count. With the notebook's `alpha=1`, we act as if each word was seen once more in each class:

$$P(w \mid c) = \frac{\text{count}(w, c) + \alpha}{\text{total words in } c + \alpha \times |V|}$$

- `w` is the word and `c` is the class, such as spam.
- `count(w, c)` is the number of occurrences of that word in that class.
- `alpha` is the extra count added to each vocabulary word.
- `|V|` is the number of different words in the shared vocabulary.
- The denominator adds `alpha × |V|` because we added `alpha` once for every vocabulary word. This keeps the counts and total consistent.

Here the vocabulary has 26 words. For spam, the denominator becomes `18 + 1 × 26 = 44`. `free` now has likelihood `(3 + 1) / 44 = 4/44`; `money` has `3/44`; and `tomorrow`, unseen in spam, has `1/44` instead of zero. Its absence makes spam less likely, but does not make spam impossible.

The next code creates the shared vocabulary and uses the smoothed likelihood in the same multiplication-based classifier.



```python
vocabulary = set(spam_words) | set(ham_words)
V = len(vocabulary)
ALPHA = 1.0

def p_smoothed(word, counts, total):
    return (counts[word] + ALPHA) / (total + ALPHA * V)

def classify_smoothed(message, verbose=True):
    words = message.split()
    score_spam, score_ham = p_spam, p_ham
    for w in words:
        score_spam *= p_smoothed(w, spam_counts, len(spam_words))
        score_ham  *= p_smoothed(w, ham_counts,  len(ham_words))
    verdict = "spam" if score_spam > score_ham else "ham"
    if verbose:
        print(f"{message}")
        print(f"  spam: {score_spam:.12f}   ham: {score_ham:.12f}   -> {verdict}")
    return verdict
print("vocabulary size:", V)
print()
classify_smoothed("free money tomorrow")
classify_smoothed("send the report tomorrow")
```


**Saved output:**

```text
vocabulary size: 26

free money tomorrow
  spam: 0.000070435763   ham: 0.000015410537   -> spam
send the report tomorrow
  spam: 0.000000133401   ham: 0.000006030210   -> ham
```


**Saved output:**

```text
'ham'
```



The saved result now labels `free money tomorrow` as spam. Its spam score is `0.5 × (4/44) × (3/44) × (1/44) = 0.000070435763`. The ham calculation uses denominator `20 + 26 = 46` and gives `0.000015410537`, so spam wins. `send the report tomorrow` still wins as ham.

Here `tomorrow` is known to the shared vocabulary but was unseen in the spam class. Smoothing lets that missing class count reduce the evidence without destroying the whole product.
