## Compare with the majority-class baseline

Real inboxes need not contain equal numbers of spam and ham. Suppose only 10% of incoming messages are spam. The next example uses 2 spam and 18 ham messages to show how accuracy can hide complete failure on the smaller class.



```python
imbalanced_texts = spam_samples[:2] + ham_samples + ham_samples[:3]
imbalanced_labels = ["spam"] * 2 + ["ham"] * (len(ham_samples) + 3)

print("class balance:", Counter(imbalanced_labels))

class AlwaysHam:
    def predict(self, texts):
        return ["ham"] * len(texts)

lazy = AlwaysHam()
lazy_pred = lazy.predict(imbalanced_texts)

print()
print("accuracy of a model that just says 'ham' every time:",
      round(accuracy_score(imbalanced_labels, lazy_pred), 3))
```


**Saved output:**

```text
class balance: Counter({'ham': 18, 'spam': 2})

accuracy of a model that just says 'ham' every time: 0.9
```



`AlwaysHam` catches no spam at all, yet its accuracy is `18 / 20 = 0.9`. The only rule is to return `ham` for every message.

On this data, 90% accuracy alone says very little. The baseline is **the proportion of the most common class**, which is 90%, rather than an assumed 50%. A useful model needs to be assessed against that baseline and against the errors that matter.



```python
print(classification_report(imbalanced_labels, lazy_pred, zero_division=0))
```


**Saved output:**

```text
              precision    recall  f1-score   support

         ham       0.90      1.00      0.95        18
        spam       0.00      0.00      0.00         2

    accuracy                           0.90        20
   macro avg       0.45      0.50      0.47        20
weighted avg       0.81      0.90      0.85        20

```



The class report makes the failure visible: spam recall is **0.00**, because neither spam message was caught. Spam precision and F1 are also zero in the saved report. Always inspect each class instead of relying on overall accuracy.
