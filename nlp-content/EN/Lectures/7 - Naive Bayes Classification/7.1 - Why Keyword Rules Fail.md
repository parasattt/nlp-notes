## Start with keyword rules

Before training a model, try a simple rule: write down words that often appear in spam, then flag a message if it contains any of them. This uses your own experience instead of learning from labelled examples.



`rule_based` lowercases a message, splits it into words, and checks whether any word belongs to `SPAM_WORDS`. Using a set means repeated keywords do not change its decision.

```python
SPAM_WORDS = {"free", "win", "winner", "prize", "click", "urgent", "cash", "offer"}

def rule_based(message):
    words = set(message.lower().split())
    return "spam" if words & SPAM_WORDS else "ham"

tests = [
    ("win a free prize click here", "spam"),
    ("urgent claim your cash offer", "spam"),
    ("the meeting is at three tomorrow", "ham"),
    ("please send the quarterly report", "ham"),
]

for text, truth in tests:
    print(f"{rule_based(text):5} (should be {truth:5}) | {text}")
```


**Saved output:**

```text
spam  (should be spam ) | win a free prize click here
spam  (should be spam ) | urgent claim your cash offer
ham   (should be ham  ) | the meeting is at three tomorrow
ham   (should be ham  ) | please send the quarterly report
```



The rule gets all four initial examples right. That looks promising, but four easy examples do not show whether it works on ordinary mail. The next two messages are both legitimate.



```python
awkward = [
    ("are you free for lunch on thursday", "ham"),
    ("click the link in the onboarding doc when you get a chance", "ham"),
]

for text, truth in awkward:
    got = rule_based(text)
    flag = "  <-- WRONG" if got != truth else ""
    print(f"{got:5} (should be {truth:5}) | {text}{flag}")
```


**Saved output:**

```text
spam  (should be ham  ) | are you free for lunch on thursday  <-- WRONG
spam  (should be ham  ) | click the link in the onboarding doc when you get a chance  <-- WRONG
```



The rule wrongly sends both messages to spam. These mistakes can be expensive: a colleague's lunch invitation may disappear into the spam folder and never be read.

The main problem is the kind of decision the rule makes. `free` really does occur more often in spam, but that does not mean every message containing `free` is spam. Adding another keyword does not solve this problem. A hard yes/no rule cannot describe **how much evidence** a word gives.

Instead, we can count how words are used in labelled data and use those counts to measure the evidence.
