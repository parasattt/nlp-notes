## Inspect the evidence learned for each word

`feature_log_prob_` stores $\log P(w \mid c)$ for every vocabulary word in each class. These are the log word likelihoods from the earlier calculation.

The next cell subtracts the ham value from the spam value for each word. A positive `spam_vs_ham` value favours spam; a negative value favours ham. Sorting the differences reveals which words provide the strongest evidence in each direction.



Class indices are looked up from `clf.classes_` instead of assuming an order. The code builds and sorts a table of log-likelihood differences, keeping the feature names aligned with the probability columns.

```python
feature_names = vec2.get_feature_names_out()
spam_idx = list(clf.classes_).index("spam")
ham_idx  = list(clf.classes_).index("ham")

log_ratio = clf.feature_log_prob_[spam_idx] - clf.feature_log_prob_[ham_idx]

ranked = pd.DataFrame({"word": feature_names, "spam_vs_ham": log_ratio})
ranked = ranked.sort_values("spam_vs_ham", ascending=False)

print("MOST SPAM-LIKE")
print(ranked.head(10).to_string(index=False))
print()
print("MOST HAM-LIKE")
print(ranked.tail(10).to_string(index=False))
```

The spam end looks sensible: `click`, `free`, `claim`, `win`, and `prize`. These were learned from word counts, rather than written into the classifier as rules.

The ham end needs closer inspection. Plausible-looking words can still reveal a shortcut learned from an unrepresentative dataset.



The notebook points to formal-mail words such as `please`, `thank`, `dear`, `report`, and `meeting` as ham evidence. Look at the ham examples themselves: they are all formal office emails, with greetings and full punctuation.

The model therefore partly learns **formal office writing versus promotional writing**, as well as spam versus legitimate mail. Those patterns happen to line up in this collection. Counts alone do not tell the model which pattern matters and which is only an accident of how the data was written.



```python
informal_but_legitimate = [
    "hey are you free for lunch tomorrow",
    "call me now urgent",
    "got the thing sorted, all good",
]

for msg in informal_but_legitimate:
    pred = clf.predict(vec2.transform([msg]))[0]
    conf = clf.predict_proba(vec2.transform([msg]))[0].max()
    print(f"{pred:5} ({conf:.0%}) | {msg}")
```


**Saved output:**

```text
ham   (68%) | hey are you free for lunch tomorrow
spam  (88%) | call me now urgent
ham   (88%) | got the thing sorted, all good
```



All three new messages are legitimate, but the saved classifier labels `call me now urgent` as spam with 88% confidence. It labels the lunch invitation ham with only 68% confidence, much less certainty than the formal test emails. The third message gets 88% ham.

`call me now urgent` could be an ordinary message from a colleague when something has gone wrong. In this training data, however, `now` and `urgent` occurred only in spam. The model responds to the evidence it was given, so informal legitimate mail can look unlike the narrow kind of ham it knows.

This is a **dataset bias** problem, rather than a defect specific to Naive Bayes. Another classifier trained on the same narrow examples can learn the same shortcut. A test set drawn from the same source often shares the training set's blind spots, so a high test score may never reveal them. The origin and variety of the data shape what the model can learn.
