#### Where it goes wrong: out-of-order execution

The notebook's state depends on the **order you ran the cells**, rather than only on their order on screen. Python lets you run cell 10, then cell 3, then cell 7.

As a result, a notebook can work for its author but fail for someone who opens it and runs it from top to bottom. The author's session may contain values created by an earlier run that the new session does not have.

The next demonstration is deliberately meant to show this problem: first set `total` to zero, then run the incrementing cell several times.



```python
# Run this cell FIRST.
total = 0
```



```python
# Then run this one a few times in a row. Watch the number change each time.
total = total + 1
print("total is now:", total)
```


**Saved output:**

```text
total is now: 1
```

Each run adds one to the current value of `total`. The saved output records one run after the reset, giving `1`; it does not record a fresh execution of the whole notebook.



If you run the incrementing cell three times after the reset, `total` becomes 3. Someone running the notebook once from a fresh session gets 1. The displayed cell alone does not reveal how many times you ran it.

Build this habit: when your work is finished, use **Runtime → Restart session and run all**. Check that it works from a clean start, in page order. A result is **reproducible** when another clean run can produce it again. If the notebook needs hidden session history, it does not yet give a reproducible result.
