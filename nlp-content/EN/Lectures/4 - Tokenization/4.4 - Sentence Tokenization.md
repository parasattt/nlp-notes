## Sentence tokenization

Sometimes the useful unit is a sentence. Splitting at every `.` fails because a dot does not always end a sentence. Compare the earlier [[EN/Lectures/3 - Parsing Text and Regex/3.10 - Sentence Splitting and Lookarounds|regex sentence-splitting example]].



The following code prints every result from splitting the paragraph at a literal dot. `repr` makes the leading spaces and final empty string visible.

```python
para = "Dr. Smith arrived at 3 p.m. He was late. The meeting cost $1.5 million. Everyone left."

print("naive split on '.':")
for s in para.split("."):
    print("   ", repr(s))
```


**Saved output:**

```text
naive split on '.':
    'Dr'
    ' Smith arrived at 3 p'
    'm'
    ' He was late'
    ' The meeting cost $1'
    '5 million'
    ' Everyone left'
    ''
```



`Dr.`, `p.m.` and `1.5` contain dots that do not end sentences, so the simple split breaks them apart.

**Source discrepancy:** the notebook describes this as “six fragments” instead of four sentences. The saved output actually shows eight strings: seven nonempty fragments and a final empty string. The code and saved output are preserved above.



`sent_tokenize` instead identifies sentence boundaries. Compare its four saved results with the broken pieces above.

```python
from nltk.tokenize import sent_tokenize

for s in sent_tokenize(para):
    print("-", s)
```


**Saved output:**

```text
- Dr. Smith arrived at 3 p.m.
- He was late.
- The meeting cost $1.5 million.
- Everyone left.
```



`sent_tokenize` returns the intended four sentences here. The lecture explains it as a small trained model, which lets it recognise that an abbreviation such as `Dr.` does not end this sentence.
