## Splitting on whitespace

`.split()` splits a string at whitespace. It works well for this clean sentence. The [[EN/Lectures/1 - Python Basics for Text/1.9 - Splitting and Joining Text|Python basics lecture]] explains the string operations behind it.



```python
text = "Natural language processing is useful"
print(text.split())
```


**Saved output:**

```text
['Natural', 'language', 'processing', 'is', 'useful']
```



Now try a more realistic string.



```python
messy = "Dr. Smith didn't pay $19.99 for the U.S.A. trip... Wasn't that great?! :) #nlp @ai_lab"

print(messy.split())
```


**Saved output:**

```text
['Dr.', 'Smith', "didn't", 'pay', '$19.99', 'for', 'the', 'U.S.A.', 'trip...', "Wasn't", 'that', 'great?!', ':)', '#nlp', '@ai_lab']
```



The result has several problems:

- `great?!` and `trip...` still have punctuation attached. They become different tokens from `great` and `trip`.
- Should `didn't` be one token or two? The task must decide.
- `:)` stayed whole. That is useful because the smiley carries sentiment.

Attached punctuation can quietly make word counts misleading.



```python
reviews = "great! great. great great?! GREAT"
print(Counter(reviews.split()))
```


**Saved output:**

```text
Counter({'great!': 1, 'great.': 1, 'great': 1, 'great?!': 1, 'GREAT': 1})
```



There are five mentions of the same word, but the counter reports five different strings with a count of 1 each.



## A second attempt: strip punctuation



`tokenize_v2` splits at whitespace, strips the listed characters from each token’s ends, lowercases nonempty results and discards tokens stripped to nothing. It does not remove punctuation from inside a token.

```python
def tokenize_v2(text):
    tokens = []
    for word in text.split():
        word = word.strip('.,!?;:"()[]{}-\'')
        if word:
            tokens.append(word.lower())
    return tokens

print(tokenize_v2(reviews))
print()
print(tokenize_v2(messy))
```


**Saved output:**

```text
['great', 'great', 'great', 'great', 'great']

['dr', 'smith', "didn't", 'pay', '$19.99', 'for', 'the', 'u.s.a', 'trip', "wasn't", 'that', 'great', '#nlp', '@ai_lab']
```



All five versions of `great` now match, but the change creates other problems:

- `:)` disappears completely. It contains only punctuation, so stripping leaves an empty string.
- `u.s.a.` loses its final dot. It will no longer match another token written as `u.s.a.`.

Adding a rule to fix one example can break another. A tokenizer designed for the data gives us a better starting point.
