**3. Find the duplicate complaints.**

These messages include three pairs describing the same problems in different words:

```python
inbox = [
    "My laptop battery dies within an hour",
    "Battery only lasts about 60 minutes on this laptop",
    "The screen has a dead pixel in the corner",
    "There is a stuck pixel on my display",
    "Laptop overheats when I play games",
    "Gets extremely hot during gaming",
    "Shipping was fast and packaging was good",
]
```

Write `find_duplicates(docs, threshold)` to return index pairs that probably describe the same issue.

Use Jaccard similarity on normalised token sets:

```python
def jaccard(a, b):
    return len(a & b) / len(a | b) if (a | b) else 0.0
```

Design the `normalize` step. A simple overlap method finds few pairs because `dies`/`lasts`, `screen`/`display` and `overheats`/`hot` are different strings. Choose a threshold that finds the true pairs without incorrectly matching ticket 6.

Then answer:

- Which true pair was hardest to catch, and why?
- What happens if you *keep* stop words? Try it and report the numbers.
- The source asks which pair cannot be matched by tokenization or lemmatization alone. Identify it and explain what other tool would be needed.

---

For the duplicate exercise, Jaccard similarity divides the number of shared normalized tokens (`a & b`) by the number of distinct tokens present in either set (`a | b`). A value of 0 means no overlap; a value of 1 means identical nonempty sets. The source function returns 0.0 when both sets are empty, avoiding division by zero. The choice of normalization and threshold must still be justified with the actual complaint pairs.
