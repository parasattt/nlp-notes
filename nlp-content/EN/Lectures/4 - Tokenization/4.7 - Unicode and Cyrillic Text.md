## Text beyond English



The Kazakh and Russian sample strings are kept together for the next comparisons. The first regex uses only Latin ASCII letters.

```python
kk = "Мен дүкеннен екі жаңа кітап сатып алдым. Достарыма бердім! Олар қуанды."
ru = "Мы купили два новых ноутбука в магазине. Они работали отлично!"

print("ascii pattern [a-zA-Z]+ on Kazakh:", re.findall(r"[a-zA-Z]+", kk))
```


**Saved output:**

```text
ascii pattern [a-zA-Z]+ on Kazakh: []
```



The ASCII pattern returns an empty list for this Kazakh text, without an error or warning. A pipeline using it could silently produce no tokens for Kazakh documents.

`\w+` recognises Unicode word characters and handles both alphabets in these examples. This is the same distinction explained in [[EN/Lectures/3 - Parsing Text and Regex/3.4 - Unicode-Aware Tokens|Unicode-aware regex tokens]].



Apply the Unicode-aware regex to both languages and compare the actual tokens.

```python
print("KK:", re.findall(r"\w+", kk))
print()
print("RU:", re.findall(r"\w+", ru))
```


**Saved output:**

```text
KK: ['Мен', 'дүкеннен', 'екі', 'жаңа', 'кітап', 'сатып', 'алдым', 'Достарыма', 'бердім', 'Олар', 'қуанды']

RU: ['Мы', 'купили', 'два', 'новых', 'ноутбука', 'в', 'магазине', 'Они', 'работали', 'отлично']
```



Case conversion also works with Cyrillic, including the Kazakh-specific letters in the source string.

```python
# Lowercasing works on Cyrillic, including Kazakh-specific letters.
print("ӘЛЕМ САЛЕМ Ұлы Қазақстан".lower())
```


**Saved output:**

```text
әлем салем ұлы қазақстан
```
