## Находим слова с опечатками через символьные n-граммы

В трёх отзывах `battery` написано с ошибкой: `batery` или `battry`. Сначала попробуйте правильно написанный запрос с признаками слов, чтобы увидеть, какие отзывы станут невидимыми.



```python
print("QUERY: battery")
search("battery", k=6)
```


**Сохранённый вывод:**

```text
QUERY: battery
  0.453  [negative]  disappointed the battery died within a week
  0.384  [positive]  very satisfied the battery lasts all day highly recommend
  0.000  [negative]  I would NOT recommend this to anyone
  0.000  [negative]  Lasted less than a month. Meh.
  0.000  [negative]  Not as good as the reviews suggest
  0.000  [negative]  It works but the noise is unbearable
```



Ненулевое сходство есть только у двух результатов. Отзывы с опечатками не совпадают с `battery`, потому что словесный векторизатор считает `batery` отдельным признаком, не связанным с `battery`.

Вместо целых слов можно использовать перекрывающиеся **символьные n-граммы** — короткие кусочки букв. Тогда почти одинаковые написания получат общие признаки.



```python
demo = TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 3))
demo.fit(["battery", "batery"])
print(demo.get_feature_names_out())
```


**Сохранённый вывод:**

```text
[' ba' 'ate' 'att' 'bat' 'ery' 'ry ' 'ter' 'tte']
```



`analyzer="char_wb"` строит символьные n-граммы внутри границ слов, добавляя по пробелу с каждого края. При `ngram_range=(3, 3)` каждый признак — кусочек из трёх символов.

У `battery` и `batery` много общих кусочков, включая ` ba`, `bat`, `ter`, `ery` и `ry `. Поэтому их сходство может быть ненулевым без проверки орфографии. Следующий поиск использует длины от 3 до 5, а не только 3.



`ngram_range=(3, 5)` создаёт кусочки длиной 3, 4 и 5 символов. Запрос и отзывы используют один обученный символьный словарь; меняется только представление признаков.

```python
char_tv = TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5))
char_matrix = char_tv.fit_transform(reviews)

scores = cosine_similarity(char_tv.transform(["battery"]), char_matrix)[0]
print("QUERY: battery   (character n-grams)")
for i in scores.argsort()[::-1][:6]:
    print(f"  {scores[i]:.3f}  [{review_labels[i]}]  {reviews[i]}")
print()
print("features:", len(tv_reviews.get_feature_names_out()), "(words) vs",
      len(char_tv.get_feature_names_out()), "(character n-grams)")
```


**Сохранённый вывод:**

```text
QUERY: battery   (character n-grams)
  0.449  [negative]  disappointed the battery died within a week
  0.415  [positive]  very satisfied the battery lasts all day highly recommend
  0.172  [positive]  The batery easily lasts 2 days with heavy use
  0.162  [negative]  I wanted to love it but the batery stopped charging after a month
  0.136  [negative]  The battry drains overnight even when switched off
  0.068  [negative]  Expected much better from this brand

features: 376 (words) vs 3950 (character n-grams)
```



Теперь все три отзыва с опечатками появляются ниже двух правильно написанных отзывов о батарее. Совпадение символов может помогать также с `recieved`/`received`, `colour`/`color` и формами вроде `charge`, `charging` и `charger`.

Сохранённое число признаков показывает одну цену: вместо 376 словесных признаков получаем 3,950 символьных, примерно в десять раз больше. Есть и другая цена: похожее написание не всегда означает похожий смысл. Следующее сравнение проверяет это напрямую.



```python
pairs = [("happy", "unhappy"), ("the seller was helpful", "the seller was unhelpful")]

for p in pairs:
    w = TfidfVectorizer().fit_transform(p)
    c = TfidfVectorizer(analyzer="char_wb", ngram_range=(3, 5)).fit_transform(p)
    print(f"{str(p):52} words {cosine_similarity(w)[0, 1]:.3f}   characters {cosine_similarity(c)[0, 1]:.3f}")
```


**Сохранённый вывод:**

```text
('happy', 'unhappy')                                 words 0.000   characters 0.450
('the seller was helpful', 'the seller was unhelpful') words 0.603   characters 0.785
```



`happy` и `unhappy` противоположны по смыслу, но большинство букв общие. Со словами их сходство равно 0, с символьными n-граммами — 0.450. У предложений о продавце сходство растёт с 0.603 по словам до 0.785 по символам.

Общие признаки, которые спасают опечатку, делают похожими и противоположности. Это ещё одна форма проблемы отрицания. Стоп-список может удалить отдельное слово `not`; символьные признаки могут размыть `un` в начале слова. Любое представление делает часть входов похожими, поэтому проверяйте, подходят ли такие сходства вашей задаче.
