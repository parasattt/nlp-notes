### Шаг 4: обновляем векторы после ответа

Пусть $p$ — предсказанная вероятность, а $y$ — правильная метка: 1 для настоящей пары, 0 для искусственной. Центральный вектор обновляется так:

$$v \leftarrow v - \eta \, (p - y) \, u$$

Разберём обновление по порядку:

1. Считаем ошибку $p-y$.
2. Умножаем её на вектор соседа $u$.
3. Масштабируем изменение скоростью обучения $\eta$, задающей размер шага.
4. Вычитаем изменение из старого центрального вектора $v$.

Это знакомая идея градиентного спуска: понемногу менять параметры, чтобы уменьшать ошибку.

- Для **настоящей** пары с $p=0.3$ ошибка $= 0.3 - 1 = -0.7$. Вычитание отрицательного изменения сдвигает $v$ к $u$, увеличивая следующее скалярное произведение.
- Для **искусственной** пары с $p=0.8$ ошибка $= 0.8 - 0 = +0.8$. Изменение сдвигает $v$ от $u$.

Следующий код объединяет все четыре шага на двенадцати предложениях.

Обновление следует теме [[RUS/Lectures/9 - Logistic Regression/9.4 - Градиентный спуск с двумя признаками|градиентный спуск с двумя признаками]].



Маленькая реализация использует пятимерные векторы, трёх искусственных соседей на настоящую пару и скорость обучения 0.05. Вероятности выбора искусственных слов пропорциональны частоте в степени 0.75. `v_old` позволяет при обновлении вектора соседа использовать центральный вектор до его обновления.

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

print("sigmoid of -2, 0, 2:", sigmoid(np.array([-2, 0, 2])))

index = {w: i for i, w in enumerate(vocab)}
pairs = [(index[w], index[s[j]])                                       # step 1
         for s in toy for i, w in enumerate(s)
         for j in range(max(0, i - WINDOW), min(len(s), i + WINDOW + 1)) if j != i]
print("training pairs:", len(pairs), " first three:", [(vocab[c], vocab[o]) for c, o in pairs[:3]])

rng = np.random.default_rng(0)
DIM, NEGATIVES, LR = 5, 3, 0.05
v = rng.normal(0, 0.5, (len(vocab), DIM))      # centre vectors: random at the start
u = rng.normal(0, 0.5, (len(vocab), DIM))      # neighbour vectors

# how often each word is picked as a fake: frequency to the power 0.75, as in Word2Vec
freq = np.bincount([o for _, o in pairs], minlength=len(vocab)) ** 0.75
noise = freq / freq.sum()

def sims(vectors):
    return {f"{a}/{b}": round(float(cosine(vectors[index[a]], vectors[index[b]])), 2)
            for a, b in [("pizza", "burger"), ("waiter", "waitress"), ("pizza", "waiter"), ("delicious", "rude")]}

print("before training:", sims(v))

for epoch in range(300):                       # one epoch = one pass over all pairs
    for c, o in rng.permutation(pairs):
        fakes = rng.choice(len(vocab), NEGATIVES, p=noise)            # step 3
        for target, label in [(o, 1)] + [(f, 0) for f in fakes]:
            p = sigmoid(v[c] @ u[target])                             # step 2
            error = p - label
            v_old = v[c].copy()
            v[c] -= LR * error * u[target]                            # step 4
            u[target] -= LR * error * v_old

print("after training :", sims(v))
```


**Сохранённый вывод:**

```text
sigmoid of -2, 0, 2: [0.12 0.5  0.88]
training pairs: 128  first three: [('the', 'pizza'), ('the', 'was'), ('pizza', 'the')]
before training: {'pizza/burger': -0.39, 'waiter/waitress': -0.1, 'pizza/waiter': -0.14, 'delicious/rude': 0.41}
after training : {'pizza/burger': 1.0, 'waiter/waitress': 0.99, 'pizza/waiter': 0.68, 'delicious/rude': 0.63}
```



Вначале сохранённые сходства случайны. После 300 проходов по парам `pizza`/`burger` и `waiter`/`waitress` близки к 1; `pizza`/`waiter` и `delicious`/`rude` ниже.

Обучающие данные нигде не сообщают значения слов. Модель только отделяет настоящие пары соседей от случайных. Слова с похожими соседями в итоге получают похожие векторы.

Написанный вручную Python-цикл обрабатывает по одной паре и работает медленно. Лекция описывает gensim как гораздо более быструю реализацию — примерно миллион пар в секунду — и использует её для крупного примера.
