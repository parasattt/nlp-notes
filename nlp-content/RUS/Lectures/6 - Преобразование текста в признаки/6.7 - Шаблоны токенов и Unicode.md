## token_pattern: regex определяет, что считать



Прочитайте фактическое регулярное выражение по умолчанию, прежде чем выбирать замену.

```python
print(CountVectorizer().token_pattern)
```


**Сохранённый вывод:**

```text
(?u)\b\w\w+\b
```



Шаблон токенов по умолчанию — [[RUS/Lectures/3 - Разбор текста и регулярные выражения/3.5 - Синтаксис regex|регулярное выражение]]. Его часть `\w\w+` требует **два или более словесных символа**, а `\b` обозначает границы слова. Поэтому односимвольные слова вроде `a` и `I` исчезают. Исчезают и однобуквенные имена переменных в математическом тексте.



Короткие предложения показывают минимальную длину токена по умолчанию: и `I`, и `a` состоят из одного символа.

```python
short_words = ["I need a car", "he needs a car too"]

v = CountVectorizer()
v.fit(short_words)
print(v.get_feature_names_out())
```


**Сохранённый вывод:**

```text
['car' 'he' 'need' 'needs' 'too']
```



В сохранённом словаре нет ни `I`, ни `a`, и никакая ошибка не предупреждает об их удалении.

Затем блокнот возвращается к ASCII-шаблонам и казахскому тексту. Внимательно прочитайте следующий код и подпись к нему: они противоречат друг другу.



Исходный код сохранён точно, включая вводящую в заблуждение подпись вывода. В действительности вызов использует учитывающий Unicode шаблон `r"\w+"`.

```python
kk = [
    "мен кітап оқыдым",
    "ол мектепке барды",
    "біз дүкеннен нан алдық",
]

# The tokenizing step first, on its own - exactly the week 1 demonstration.
print("what [a-zA-Z]+ finds:", re.findall(r"\w+", kk[0]))
```


**Сохранённый вывод:**

```text
what [a-zA-Z]+ finds: ['мен', 'кітап', 'оқыдым']
```



**Расхождение в исходнике:** предыдущая подпись говорит `what [a-zA-Z]+ finds`, а пояснение утверждает, что ничего не найдено. Но код вызывает `re.findall(r"\w+", kk[0])`, учитывающий Unicode. Сохранённый результат правильно содержит `['мен', 'кітап', 'оқыдым']`.

Следующая ячейка действительно передаёт шаблон только для ASCII `r"[a-zA-Z]+"` в `CountVectorizer`. Этот отдельный пример вызывает ошибку пустого словаря.



Этот вызов действительно использует `[a-zA-Z]+`. Блок `try`/`except` перехватывает `ValueError` о пустом словаре и выводит сообщение библиотеки.

```python
try:
    ascii_only = CountVectorizer(token_pattern=r"[a-zA-Z]+")
    ascii_only.fit(kk)
except ValueError as e:
    print("ValueError:", e)
```


**Сохранённый вывод:**

```text
ValueError: empty vocabulary; perhaps the documents only contain stop words
```



Явно заданный ASCII-шаблон не может найти эти кириллические слова, поэтому `CountVectorizer` выдаёт ошибку. Без явного сбоя пустое представление могло бы сделать все документы одинаковыми для классификатора.

Сообщение предполагает: `empty vocabulary; perhaps the documents only contain stop words`. Лекция подчёркивает, что эта подсказка не объясняет настоящую причину в данном случае. В ней также сказано, что в корпусе нет стоп-слов. Для объяснения ошибки это утверждение не нужно: в вызове вообще не включался фильтр стоп-слов. Причина в том, что regex не смог сопоставить алфавит.

Считайте предложенную сообщением причину версией для проверки. Она отражает частую ошибку, ожидаемую автором библиотеки, но ваш случай может быть другим.

Шаблон по умолчанию обрабатывает Unicode в этих примерах. Ошибка появилась после замены на ASCII-шаблон. Сравните с [[RUS/Lectures/4 - Токенизация/4.7 - Unicode и кириллический текст|ранней демонстрацией токенизации кириллицы]].



Шаблон по умолчанию с поддержкой Unicode даёт десять слов словаря из того же казахского корпуса.

```python
proper = CountVectorizer()
proper.fit(kk)

print("vocabulary:", proper.get_feature_names_out())
print("size:", len(proper.get_feature_names_out()))
print(proper)
```


**Сохранённый вывод:**

```text
vocabulary: ['алдық' 'барды' 'біз' 'дүкеннен' 'кітап' 'мектепке' 'мен' 'нан' 'ол'
 'оқыдым']
size: 10
CountVectorizer()
```
