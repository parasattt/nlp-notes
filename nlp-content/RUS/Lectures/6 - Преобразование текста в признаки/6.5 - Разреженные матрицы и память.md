## Зачем нужно разреженное хранение

Матрица мешка слов содержит в основном нули: каждый документ использует лишь малую часть словаря. При словаре из 50,000 слов сообщение с 20 различными словами оставляет нулевыми 49,980 столбцов.

В **плотной матрице** память выделяется каждой ячейке, включая каждый ноль. **Разреженная матрица** хранит ненулевые значения и их позиции. SciPy использует такое представление для результата `CountVectorizer`.

Разберём небольшой пример по шагам:

1. `X.shape` равно `(4, 22)`: четыре строки документов и 22 столбца слов.
2. Всего возможных ячеек — `4 × 22 = 88`.
3. `X.nnz` равно 24: сохранены только 24 ненулевые записи.
4. Оставшиеся `88 - 24 = 64` ячейки равны нулю.
5. В напечатанных координатах `(0, 4) 1` означает, что в строке документа 0 в столбце словаря 4 находится счётчик 1.

Следующая оценка памяти показывает, почему при росте коллекции это становится необходимым.



Код сравнивает приблизительную память для плотного и разреженного хранения при предположениях исходника. Ни одна из больших матриц при этом не создаётся.

```python
n_docs, n_vocab = 50_000, 80_000

dense_gb = n_docs * n_vocab * 8 / 1024**3
sparse_gb = n_docs * 80 * 12 / 1024**3   # ~80 distinct words per document

print(f"dense  : {dense_gb:8.2f} GB")
print(f"sparse : {sparse_gb:8.4f} GB")
```


**Сохранённый вывод:**

```text
dense  :    29.80 GB
sparse :   0.0447 GB
```



## Как читать оценку памяти

В коде используются такие величины:

- `n_docs = 50_000`: число документов.
- `n_vocab = 80_000`: число столбцов словаря.
- `8`: предполагаемое число байтов на хранимое значение плотной матрицы.
- `80`: предполагаемое число различных слов словаря в одном документе.
- `12`: приблизительное число байтов на одну разреженную запись в коде, включая её позицию.
- `1024**3`: число байтов для перевода оценки в показанные единицы GB.

Оценка для плотного хранения:

$$\text{dense\_gb} = \frac{n_{docs}\,n_{vocab}\,8}{1024^3}$$

Она выделяет место для каждой комбинации документа и слова. Оценка разреженного хранения:

$$\text{sparse\_gb} = \frac{n_{docs}\,80\,12}{1024^3}$$

Она учитывает лишь около 80 ненулевых записей на документ. При предположениях исходника сохранены значения **29.80 GB для плотной матрицы** и **0.0447 GB для разреженной**. Последнее — оценка, а не точное измерение всех внутренних массивов.

Лекция называет 50,000 документов небольшим корпусом. Вызов `.toarray()` удобен для осмотра этих четырёх сообщений, но разворачивает матрицу в плотную и плохо подходит для реальных объёмов.
