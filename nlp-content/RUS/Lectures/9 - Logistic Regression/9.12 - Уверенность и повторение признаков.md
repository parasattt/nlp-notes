## Сравниваем уверенность наряду с accuracy

Если на малом наборе accuracy близки, что ещё важно? Поддержка действует на основе вероятностей, поэтому важна и уверенность ошибочных предсказаний.

`cross_val_predict(..., method="predict_proba")` выдаёт каждому отзыву вероятность от модели, обученной без фолда этого отзыва. Следующий код считает ошибки и проверяет, сколько из них сделаны с уверенностью больше 90%.



```python
from sklearn.model_selection import cross_val_predict

cv5 = StratifiedKFold(5, shuffle=True, random_state=0)
y_all = np.array(review_labels)

for name in ["NB  + counts", "LR  + tf-idf"]:
    proba = cross_val_predict(setups[name], reviews, y_all, cv=cv5, method="predict_proba")
    pred = np.array(["negative", "positive"])[proba.argmax(axis=1)]
    conf = proba.max(axis=1)
    wrong = pred != y_all

    print(name)
    print(f"  wrong predictions               : {wrong.sum()}")
    print(f"  ...of which made with >90% conf.: {(conf[wrong] > 0.9).sum()}")
    print(f"  confidence range                : {conf.min():.2f} to {conf.max():.2f}")
    print()
```


**Сохранённый вывод:**

```text
NB  + counts
  wrong predictions               : 37
  ...of which made with >90% conf.: 9
  confidence range                : 0.50 to 1.00

LR  + tf-idf
  wrong predictions               : 38
  ...of which made with >90% conf.: 0
  confidence range                : 0.50 to 0.70

```



Сохранённый pipeline NB делает 37 ошибок, из них 9 — с уверенностью выше 90%. LR делает 38 ошибок, но ни одной выше 90%; её уверенность лежит только между 0.50 и 0.70.

Для поддержки сердитая жалоба, ошибочно получившая вероятность положительного класса 0.99, может оказаться в конце списка чтения. Близкая accuracy не означает одинаково полезную уверенность.

Источник связывает чрезмерную уверенность Naive Bayes с предположением независимости. Несколько пересекающихся слов тональности перемножаются так, будто каждое — независимый признак. Это может сдвинуть результат к крайней вероятности. Следующая прямая проверка повторяет одно слово, чтобы показать эффект.



Для этой контролируемой проверки повторений оба демонстрационных pipeline обучаются на всём учебном корпусе. Код печатает вероятность отрицательного класса при одном и четырёх вхождениях `broke`.

```python
nb_fit = make_pipeline(CountVectorizer(), MultinomialNB()).fit(reviews, review_labels)
lr_fit = make_pipeline(TfidfVectorizer(), LogisticRegression(max_iter=2000)).fit(reviews, review_labels)

for t in ["broke", "broke broke broke broke"]:
    print(f"{t:26} NB P(negative)={nb_fit.predict_proba([t])[0, 0]:.3f}   "
          f"LR P(negative)={lr_fit.predict_proba([t])[0, 0]:.3f}")
```


**Сохранённый вывод:**

```text
broke                      NB P(negative)=0.789   LR P(negative)=0.642
broke broke broke broke    NB P(negative)=0.995   LR P(negative)=0.642
```



Четыре повторения `broke` меняют сохранённую отрицательную вероятность NB с 0.789 на 0.995. Частотные признаки учитывают это свидетельство четырежды. Pipeline LR + TF-IDF остаётся на 0.642, потому что нормализация делает эти два входа одинаковым вектором.

В сравнении меняются и модель, и представление. Неизменный результат LR здесь объясняется именно нормализацией TF-IDF; это не утверждение, что любое представление входа LR игнорирует повторения.
