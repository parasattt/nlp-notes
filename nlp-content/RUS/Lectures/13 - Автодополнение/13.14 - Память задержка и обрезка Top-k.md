### Измеряем память и время ответа

Автодополнение работает во время набора текста, поэтому должно быстро отвечать и помещаться в памяти. `pickle.dumps` превращает объект Python в байты; пример использует число байтов как оценку сериализованного размера таблицы.



Код оценивает сериализованные размеры с помощью `pickle.dumps`, затем повторяет подсказку 1 000 раз для измерения небольшой стоимости одного вызова. Показанные времена — сохранённые измерения источника.

```python
def mb(obj):
    return len(pickle.dumps(obj)) / 1e6

print(f"table for one word before : {mb(next_bi):6.1f} MB")
print(f"table for two words before: {mb(next_tri):6.1f} MB")

start = time.perf_counter()
for _ in range(1000):
    suggest("the food was")
print(f"one suggestion takes {(time.perf_counter() - start):.3f} ms")
```


**Сохранённый вывод:**

```text
table for one word before :   10.3 MB
```


**Сохранённый вывод:**

```text
table for two words before:   48.0 MB
one suggestion takes 0.008 ms
```



Сохранённое время подсказки — несколько тысячных миллисекунды. В этом эксперименте важнее расход памяти:

- Таблица однословных контекстов: **10.3 MB**, 35 639 разных контекстов.
- Таблица двухсловных контекстов: **48 MB**, 935 935 разных контекстов.

Добавление контекста создаёт гораздо больше записей. Поскольку редактор показывает четыре подсказки, следующий помощник сохраняет только четыре самых частых следующих слова для каждого контекста.



`keep_top` создаёт новые словари только с `k` самыми частыми продолжениями каждой строки. Это эксперимент с хранением; оговорка о суммах вероятностей из следующего абзаца остаётся важной.

```python
def keep_top(table, k=4):
    return {start: Counter(dict(counter.most_common(k))) for start, counter in table.items()}

print(f"two words before, top 4 only: {mb(keep_top(next_tri)):6.1f} MB")
print(f"one word before,  top 4 only: {mb(keep_top(next_bi)):6.1f} MB")
```


**Сохранённый вывод:**

```text
two words before, top 4 only:   36.1 MB
one word before,  top 4 only:    1.7 MB
```



Сохранение только четырёх лучших уменьшает однословную таблицу с **10.3 до 1.7 MB**, примерно в шесть раз. Двухсловная уменьшается с **48.0 до 36.1 MB** — экономия меньше.

Почему? Имеется 2 897 333 тройки для 935 935 контекстов — в среднем примерно три следующих слова на контекст. Поэтому ограничение четырьмя удаляет мало записей. Большинство места занимают многочисленные отдельные контексты.

Есть и деталь вероятностей: после обрезки `suggest` делила бы только на сумму оставшихся частот. Порядок подсказок тот же, но показываемые вероятности изменятся. Если нужны проценты, сохраняйте исходные суммы строк.
