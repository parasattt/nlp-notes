## Очень маленькие произведения и underflow



Этот цикл выводит накопленное произведение после каждых четырёх слов и в конце. Он нужен, чтобы показать масштаб чисел, а не обучить новую модель.

```python
long_message = "free money click now win cash prize urgent claim your free prize now today"

score = p_spam
for i, w in enumerate(long_message.split(), 1):
    score *= p_smoothed(w, spam_counts, len(spam_words))
    if i % 4 == 0 or i == len(long_message.split()):
        print(f"after {i:2} words: {score:.3e}")
```


**Сохранённый вывод:**

```text
after  4 words: 1.441e-05
after  8 words: 1.384e-10
after 12 words: 1.772e-15
after 14 words: 2.746e-18
```



При каждом умножении используется вероятность меньше 1, поэтому произведение быстро уменьшается. Сохранённый пример заканчивается после 14 слов значением `2.746e-18`. В исходном объяснении сказано, что после тринадцати слов получается $10^{-19}$. Это не совпадает с сохранённым примером, но оба случая показывают одну проблему: произведения становятся очень маленькими.

Для письма из 300 слов источник приводит $10^{-400}$, чтобы показать **underflow** — потерю слишком малого значения: число, которое слишком мало для 64-битного float, сохраняется как `0.0`. Если обе оценки классов так превращаются в ноль, снова возникает ничья.

Решение — использовать **логарифмы вероятностей**:

$\log(a \times b) = \log a + \log b$

Вместо умножения вероятностей берём их логарифмы и складываем. Начинаем с логарифма априорной вероятности, затем добавляем по одному логарифму вероятности каждого слова. Логарифм сохраняет порядок оценок: у класса с большим произведением логарифмическая оценка тоже больше. Накопленные значения остаются в удобном для хранения масштабе.



```python
def classify_log(message):
    words = message.split()
    score_spam = np.log(p_spam)
    score_ham  = np.log(p_ham)
    for w in words:
        score_spam += np.log(p_smoothed(w, spam_counts, len(spam_words)))
        score_ham  += np.log(p_smoothed(w, ham_counts,  len(ham_words)))
    return score_spam, score_ham, ("spam" if score_spam > score_ham else "ham")

s, h, verdict = classify_log(long_message)
print(f"log spam: {s:.2f}")
print(f"log ham : {h:.2f}")
print("verdict :", verdict)
```


**Сохранённый вывод:**

```text
log spam: -40.44
log ham : -53.60
verdict : spam
```



Логарифмические оценки равны `-40.44` для spam и `-53.60` для ham. Spam по-прежнему побеждает, потому что `-40.44` больше. Отрицательная оценка нормальна: эти вероятности меньше 1, а логарифм числа между 0 и 1 отрицателен.

Поэтому реализации используют логарифмическую шкалу, а атрибут модели с вероятностями слов дальше называется `feature_log_prob_`.
