## Две проблемы прямого умножения

Классификатор, написанный вручную, показывает основную идею. Но у такой прямой реализации две проблемы: нулевая вероятность слова может стереть все свидетельства, а длинное произведение может стать слишком маленьким для хранения в компьютере.



### Нулевая вероятность стирает влияние других слов



```python
classify_by_hand("free money tomorrow")
```


**Сохранённый вывод:**

```text
message   : free money tomorrow
spam score: 0.0000000000
ham score : 0.0000000000
verdict   : ham

```



Обе оценки равны нулю, поэтому выведенный ответ `ham` бесполезен. Код использует `>`; при равенстве двух нулей выбирается ветка `else`.

`tomorrow` не встречалось в обучающем спаме, поэтому $P(\text{tomorrow} \mid \text{spam}) = 0$. Умножение на этот ноль стирает свидетельства от `free` и `money`. Для ham вероятности этих слов тоже нулевые, поэтому и его оценка становится нулём.

Конечная обучающая коллекция не может содержать каждое слово в каждом классе. Такое будет происходить регулярно. Поэтому «не встречалось в этом классе» нужно отличать от «невозможно в этом классе».



## Сглаживание Лапласа

**Сглаживание Лапласа**, также называемое аддитивным сглаживанием, добавляет небольшую величину к частоте каждого слова словаря. При значении `alpha=1` из блокнота мы как будто ещё один раз увидели каждое слово в каждом классе:

$$P(w \mid c) = \frac{\text{count}(w, c) + \alpha}{\text{total words in } c + \alpha \times |V|}$$

- `w` — слово, а `c` — класс, например spam.
- `count(w, c)` — число вхождений этого слова в этот класс.
- `alpha` — добавка к частоте каждого слова словаря.
- `|V|` — число разных слов в общем словаре.
- В знаменатель добавляется `alpha × |V|`, потому что для каждого слова словаря мы один раз добавили `alpha`. Так сумма частот остаётся согласованной с общим числом.

Здесь в словаре 26 слов. Для spam знаменатель становится `18 + 1 × 26 = 44`. У `free` вероятность теперь `(3 + 1) / 44 = 4/44`, у `money` — `3/44`, а у `tomorrow`, которого в спаме не было, — `1/44` вместо нуля. Его отсутствие делает spam менее вероятным, но не невозможным.

Следующий код создаёт общий словарь и подставляет сглаженную вероятность в тот же классификатор с умножением.



```python
vocabulary = set(spam_words) | set(ham_words)
V = len(vocabulary)
ALPHA = 1.0

def p_smoothed(word, counts, total):
    return (counts[word] + ALPHA) / (total + ALPHA * V)

def classify_smoothed(message, verbose=True):
    words = message.split()
    score_spam, score_ham = p_spam, p_ham
    for w in words:
        score_spam *= p_smoothed(w, spam_counts, len(spam_words))
        score_ham  *= p_smoothed(w, ham_counts,  len(ham_words))
    verdict = "spam" if score_spam > score_ham else "ham"
    if verbose:
        print(f"{message}")
        print(f"  spam: {score_spam:.12f}   ham: {score_ham:.12f}   -> {verdict}")
    return verdict
print("vocabulary size:", V)
print()
classify_smoothed("free money tomorrow")
classify_smoothed("send the report tomorrow")
```


**Сохранённый вывод:**

```text
vocabulary size: 26

free money tomorrow
  spam: 0.000070435763   ham: 0.000015410537   -> spam
send the report tomorrow
  spam: 0.000000133401   ham: 0.000006030210   -> ham
```


**Сохранённый вывод:**

```text
'ham'
```



Теперь сохранённый результат относит `free money tomorrow` к spam. Его оценка spam равна `0.5 × (4/44) × (3/44) × (1/44) = 0.000070435763`. В расчёте ham знаменатель `20 + 26 = 46` даёт `0.000015410537`, поэтому побеждает spam. Для `send the report tomorrow` по-прежнему побеждает ham.

Здесь `tomorrow` входит в общий словарь, но не встречалось в классе spam. Благодаря сглаживанию этот нулевой счётчик ослабляет свидетельство, не уничтожая всё произведение.
