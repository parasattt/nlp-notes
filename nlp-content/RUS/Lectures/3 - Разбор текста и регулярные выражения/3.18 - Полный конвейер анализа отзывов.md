## Соберём весь процесс вместе

Следующий пример объединяет первые четыре notebook в практическом порядке. Источник предлагает его как шаблон для будущих заданий: сохранить исходные сигналы, очистить, токенизировать, проанализировать и проверить, подтверждаются ли наблюдения.

```python
corpus = [
```

```python
# --- Step 2: clean ---
def clean(t):
    t = re.sub(r"<[^>]+>", " ", t)
    t = re.sub(r"https?://\S+", " <url> ", t)
    t = re.sub(r"\S+@\S+\.\S+", " <email> ", t)
    t = re.sub(r"\d{4}-\d{2}-\d{2}", " <date> ", t)     # specific before general
    t = re.sub(r"\+?\d[\d\s\-()]{7,}\d", " <phone> ", t)
    t = t.lower()
    t = re.sub(r"\s+", " ", t)
    return t.strip()

df["clean"] = df["raw"].apply(clean)
df[["raw", "clean"]].head(4)
```

Последовательность очистки снова использует правило [[RUS/Lectures/3 - Разбор текста и регулярные выражения/3.9 - Маркеры и порядок правил очистки#^specific-before-general|конкретные шаблоны перед общими]].



```python
# --- Step 3: tokenize ---
STOP = {"the","a","an","is","was","are","were","in","on","at","to","for","of",
        "and","but","or","it","this","that","i","my","me","you","be","so","very",
        "url","email","phone","date"}

def tokenize(t):
    tokens = re.findall(r"[a-z]+", t)
    return [w for w in tokens if w not in STOP and len(w) > 2]

df["tokens"] = df["clean"].apply(tokenize)
df["n_tokens"] = df["tokens"].str.len()
df[["clean", "tokens"]].head(4)
```

```python
# --- Step 4: analyse ---
#print(df)
df["sentiment"] = df["rating"].apply(lambda r: "positive" if r >= 4 else ("negative" if r <= 2 else "neutral"))

pos_words = [w for row in df.loc[df["sentiment"] == "positive", "tokens"] for w in row]
neg_words = [w for row in df.loc[df["sentiment"] == "negative", "tokens"] for w in row]

print("Top words in POSITIVE reviews:")
for w, n in Counter(pos_words).most_common(8):
    print(f"   {w:<12} {n}")

print("\nTop words in NEGATIVE reviews:")
for w, n in Counter(neg_words).most_common(8):
    print(f"   {w:<12} {n}")
```

Назначение меток использует [[RUS/Lectures/1 - Основы Python для работы с текстом/1.13 - Условия и тональность по ключевым словам|условные выражения и правила тональности]], а выбор строк — [[RUS/Lectures/2 - Pandas для текстовых данных/2.19 - Индексация по меткам и позициям|выбор по меткам с loc]].



Относитесь к этим рейтингам осторожно. Отзывов всего восемь, а большинство слов встречается один раз. Поэтому «восемь самых частых» близко к «первым восьми встреченным словам», а не к убедительным данным о классах.

Источник называет положительные слова *great*, *love* и *excellent*, а также отрицательные *broke*, *terrible* и *worst*. При таком небольшом числе наблюдений на список влияют и полезный сигнал, и шум.

На десяти тысячах отзывов тот же метод мог бы быть гораздо информативнее. Отличайте разумный метод от выборки, слишком маленькой для уверенного вывода.



```python
# --- Step 5: do the non-text features carry signal? ---
```

Сохранённые средние по группам показывают `n_caps` 1.00 для отрицательных отзывов и 0.33 для положительных. Это согласуется с идеей, что рассерженные авторы могут использовать больше заглавных букв.

Но разница возникает из-за **одного отзыва**, `WORST PURCHASE EVER`. Уберите его — и закономерность исчезнет. Трёх отрицательных отзывов недостаточно для общего правила. ^small-sample-warning

Осторожный вывод — «это может быть полезным признаком, который стоит проверить на реальных данных», а не «отрицательные отзывы содержат больше заглавных букв». Лекция предлагает формулировать утверждения первого типа, не считая маленький пример доказательством.

Процесс всё же показывает основной подход: превратить неаккуратный исходный текст в структурированные числа, затем задать вопрос достаточно точно для проверки. На этой подготовке основаны векторизация, классификаторы, векторные представления и трансформеры.
