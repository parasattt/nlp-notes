## Начнём с разбиения по пробельным символам

Первая задача — превратить предложение в список слов. Для аккуратного предложения разбиения по пробельным символам кажется достаточно.



```python
text = "Natural language processing is useful"
print(text.split())
```


**Сохранённый вывод:**

```text
['Natural', 'language', 'processing', 'is', 'useful']
```



Аккуратный пример работает. Теперь попробуйте текст с пунктуацией, сокращённой формой слова, кавычками и сокращением перед именем.



```python
real = "Dr. Smith said: \"NLP is hard, isn't it?\" -- he wasn't wrong!"
print(real.split())
```


**Сохранённый вывод:**

```text
['Dr.', 'Smith', 'said:', '"NLP', 'is', 'hard,', "isn't", 'it?"', '--', 'he', "wasn't", 'wrong!']
```



Посмотрите на токены в сохранённом результате:

- У `'said:'` осталось двоеточие.
- У `'"NLP'` осталась открывающая кавычка.
- `'hard,'` будет подсчитано отдельно от `'hard'`.
- К `'it?"'` присоединены два знака пунктуации.
- `'--'` считается словом.

Это не просто проблемы отображения. Когда вхождения одного слова распределяются по разным токенам, подсчёты слов и построенные на них признаки становятся менее полезными. Это может ухудшить последующую модель.

### Попробуем убрать пунктуацию с краёв

Следующая функция удаляет указанный набор знаков пунктуации с краёв каждого токена и переводит оставшийся текст в нижний регистр.



```python
def tokenize_v2(text):
    tokens = []
    for word in text.split():
        word = word.strip('.,!?;:"()[]{}-\'')
        if word:
            tokens.append(word.lower())
    return tokens

print(tokenize_v2(real))
```


**Сохранённый вывод:**

```text
['dr', 'smith', 'said', 'nlp', 'is', 'hard', "isn't", 'it', 'he', "wasn't", 'wrong']
```

Используемые здесь строковые операции объясняются в темах [[RUS/Lectures/1 - Основы Python для работы с текстом/1.5 - Очистка строк и пробельные символы|методы очистки строк]] и [[RUS/Lectures/1 - Основы Python для работы с текстом/1.9 - Разбиение и объединение текста|разбиение и объединение текста]].



Первый пример стал лучше. Теперь проверим текст с электронным адресом, номером телефона, ценой и процентом.



```python
tricky = "Email me at ivan@mail.kz or call +7-701-555-0199. Cost: $19.99 (30% off!)"
print(tokenize_v2(tricky))
```


**Сохранённый вывод:**

```text
['email', 'me', 'at', 'ivan@mail.kz', 'or', 'call', '+7-701-555-0199', 'cost', '$19.99', '30%', 'off']
```



Сохранённый результат:

```text
['email', 'me', 'at', 'ivan@mail.kz', 'or', 'call',
 '+7-701-555-0199', 'cost', '$19.99', '30%', 'off']
```

Электронный адрес, телефон и цена остались **целыми**. Полезно ли это, зависит от задачи, но данный токенизатор явно не задаёт такой выбор.

`strip()` удаляет символы только с **краёв** токена. Пунктуация в середине остаётся из-за своего положения, а не потому, что программа распознала электронный адрес или цену. В следующих примерах пунктуация перемещается между серединой и краями.



```python
print(tokenize_v2("Ready? (yes) -- the answer's 42."))
print(tokenize_v2("He said 'hello'."))
print(tokenize_v2("Rating: 4/5. Cost-benefit: good."))
```


**Сохранённый вывод:**

```text
['ready', 'yes', 'the', "answer's", '42']
['he', 'said', 'hello']
['rating', '4/5', 'cost-benefit', 'good']
```



Один и тот же апостроф обрабатывается по-разному в двух позициях: в `answer's` он остаётся, а из `'hello'` удаляются оба окружающих апострофа. Так же `4/5` остаётся целым, а `(yes)` теряет скобки.

Добавление символов в список удаления не решает основную проблему. Функция растёт, причины её исключений всё труднее помнить, а поведение токенов по-прежнему зависит от положения символа.

Такой подход описывает **что удалять**. Более полезное правило может описывать **как должно выглядеть слово**.
