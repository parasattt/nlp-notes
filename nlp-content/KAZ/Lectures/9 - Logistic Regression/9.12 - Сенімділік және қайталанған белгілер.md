## Accuracy-мен бірге сенімділікті салыстырамыз

Аз деректе accuracy мәндері жақын болса, тағы не маңызды? Қолдау командасы ықтималдықтарға сүйеніп әрекет етеді, сондықтан қате болжамдардың сенімділігі де маңызды.

`cross_val_predict(..., method="predict_proba")` әр пікірге оның фолдынсыз оқытылған модельден ықтималдық береді. Келесі код қате болжамдарды санап, олардың қаншасы 90%-дан жоғары сенімділікпен жасалғанын сұрайды.



```python
from sklearn.model_selection import cross_val_predict

cv5 = StratifiedKFold(5, shuffle=True, random_state=0)
y_all = np.array(review_labels)

for name in ["NB  + counts", "LR  + tf-idf"]:
    proba = cross_val_predict(setups[name], reviews, y_all, cv=cv5, method="predict_proba")
    pred = np.array(["negative", "positive"])[proba.argmax(axis=1)]
    conf = proba.max(axis=1)
    wrong = pred != y_all

    print(name)
    print(f"  wrong predictions               : {wrong.sum()}")
    print(f"  ...of which made with >90% conf.: {(conf[wrong] > 0.9).sum()}")
    print(f"  confidence range                : {conf.min():.2f} to {conf.max():.2f}")
    print()
```


**Сақталған нәтиже:**

```text
NB  + counts
  wrong predictions               : 37
  ...of which made with >90% conf.: 9
  confidence range                : 0.50 to 1.00

LR  + tf-idf
  wrong predictions               : 38
  ...of which made with >90% conf.: 0
  confidence range                : 0.50 to 0.70

```



Сақталған NB pipeline 37 қате жасайды; оның 9-ы 90%-дан жоғары сенімділікпен жасалған. LR 38 қате жасайды, бірақ ешбірі 90%-дан жоғары емес; оның сенімділігі тек 0.50–0.70 аралығында.

Қолдау үшін ашулы шағымға қате түрде 0.99 оң ықтималдық беру оны оқу тізімінің соңына түсіруі мүмкін. Ұқсас accuracy сенімділіктің бірдей пайдалы екенін білдірмейді.

Дереккөз Naive Bayes моделінің шамадан тыс сенімділігін тәуелсіздік жорамалымен байланыстырады. Бірін-бірі қайталайтын бірнеше тональділік сөзі әрқайсысы тәуелсіз дәлел сияқты көбейтіледі, сондықтан ықтималдық шеткі мәнге жақындауы мүмкін. Келесі тікелей тексеру бір сөзді қайталап, осы әсерді көрсетеді.



Бұл бақыланатын қайталау сынағында мысалда қолданылған екі pipeline да толық оқу корпусында оқытылады. Код `broke` бір рет және төрт рет кездескендегі теріс класс ықтималдығын шығарады.

```python
nb_fit = make_pipeline(CountVectorizer(), MultinomialNB()).fit(reviews, review_labels)
lr_fit = make_pipeline(TfidfVectorizer(), LogisticRegression(max_iter=2000)).fit(reviews, review_labels)

for t in ["broke", "broke broke broke broke"]:
    print(f"{t:26} NB P(negative)={nb_fit.predict_proba([t])[0, 0]:.3f}   "
          f"LR P(negative)={lr_fit.predict_proba([t])[0, 0]:.3f}")
```


**Сақталған нәтиже:**

```text
broke                      NB P(negative)=0.789   LR P(negative)=0.642
broke broke broke broke    NB P(negative)=0.995   LR P(negative)=0.642
```



`broke` сөзін төрт рет қайталау сақталған NB теріс ықтималдығын 0.789-дан 0.995-ке өзгертеді. Жиілік белгілері бұл дәлелді төрт рет санайды. LR + TF-IDF pipeline 0.642 деңгейінде қалады, себебі нормализация осы екі кірісті бірдей вектор етеді.

Бұл салыстыру модельді де, ұсынуды да өзгертеді. Мұнда LR нәтижесінің өзгермеуі дәл TF-IDF нормализациясынан болады; бұл LR-дің кез келген кіріс ұсынуы қайталауды елемейді деген сөз емес.

Осы шағын корпуста LR ықтималдықтары сақтықпен берілген, бірақ олардың мінсіз калибрленгені дәлелденбеген. Кейінгі регуляризация баптауы осы сақтықтың қалай өзгеретінін көрсетеді.
